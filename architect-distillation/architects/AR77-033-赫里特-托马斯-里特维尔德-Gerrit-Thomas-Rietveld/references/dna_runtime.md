# AR77-033｜DESIGN DNA RUNTIME
## Gerrit Thomas Rietveld

每个项目默认只选 **2–4 个 DNA**。数量不是目标；只选解决当前空间冲突的必要机制。

## D01｜SPACE BEFORE MASS｜空间先于体量
**判断含义**：空间关系优先于完整体块。
**Trigger**：实体体量正在掩盖真正的使用、连通或开放问题。
**Spatial Operation**：先画空隙、连续区域、必须分隔区域，再生成边界。
**适用边界**：早期概念、住宅、公共与展示空间。
**Failure Mode**：把“开放”误成没有边界。
**可验证空间痕迹**：平面先读到空间连续与分隔逻辑，而不是单一雕塑体。

## D02｜INDEPENDENT LINES / PLANES / PARTS｜线、面、部件独立
**判断含义**：构件职责清楚，空间由彼此关系形成，不必熔成单一实体。
**Trigger**：空间组织需要清楚区分支撑、围护、分隔、家具或视觉层。
**Spatial Operation**：把系统拆成可识别层并校验交接点。
**适用边界**：构造、室内、立面与空间系统协同。
**Failure Mode**：为了“构成感”任意错位或加色。
**可验证空间痕迹**：剖面 / 节点中各层职责可说明，不靠装饰线条伪装。

## D03｜TRANSFORMABLE PARTITION｜可变分隔
**判断含义**：当生活变化真实存在时，固定房间不是唯一答案。
**Trigger**：同一空间存在互斥或轮换使用状态。
**Spatial Operation**：固定服务核 + 可移动 / 可转换分隔 + 明确收纳与停放位置。
**适用边界**：住宅、学习、会议、社区空间。
**Failure Mode**：移动墙只在效果图里移动，现实中因声学、消防、家具、轨道维护而失效。
**可验证空间痕迹**：至少两种使用状态平面都成立，并有转换路径。

## D04｜CONSTRUCTION AS SPATIAL ORDER｜构造即空间秩序
**判断含义**：构造关系直接参与空间组织。
**Trigger**：结构、连接、模块或部件会决定空间尺度与节奏。
**Spatial Operation**：从构件跨度、连接和职责建立空间网格或关系。
**适用边界**：需要建造逻辑清楚的项目。
**Failure Mode**：未经工程验证就把“轻”“悬”“薄”当结构事实。
**可验证空间痕迹**：平剖关系能解释构造如何支持空间，不只靠视觉表现。

## D05｜STANDARD ELEMENT ECONOMY｜标准构件经济
**判断含义**：优先利用标准尺寸、重复和简化生产解决真实资源约束。
**Trigger**：预算、工期、批量、采购或装配是关键变量。
**Spatial Operation**：建立有限部件族与重复规则，再允许必要变体。
**适用边界**：住宅、重复单元、预算敏感项目。
**Failure Mode**：模块化变成僵化，或为了“工业感”强行暴露标准件。
**可验证空间痕迹**：构件表 / 模数图与平面变化之间有因果关系。

## D06｜SMALL-SCALE PROTOTYPE｜小尺度原型
**判断含义**：家具、内置构件和小模型可测试建筑空间的比例、连接与行为。
**Trigger**：坐、靠、收纳、移动、分隔等身体尺度直接影响房间。
**Spatial Operation**：先用 1:1 / 局部模型验证，再放大到建筑系统。
**适用边界**：住宅、学习、展览、公共室内。
**Failure Mode**：把经典家具轮廓复制进建筑。
**可验证空间痕迹**：局部样段测试能反向修改平面 / 剖面，而非只是添家具。

## D07｜LIGHT AS SPATIAL MEDIUM｜光作为空间介质
**判断含义**：光不是表皮效果，而是定义空隙、观看与空间层次的条件。
**Trigger**：展示、公共空间或室内体验高度依赖日光。
**Spatial Operation**：先验证方向、眩光、热与保护要求，再组织开口和边界。
**适用边界**：文化、展示、学习、公共空间。
**Failure Mode**：把“大玻璃”误当采光策略。
**可验证空间痕迹**：剖面能说明光的路径与控制，而不是只写“通透”。

## D08｜POROUS THRESHOLD / CONTINUITY｜渗透边界 / 内外延续
**判断含义**：边界可以定义空间而不完全封闭，内部空间可向外继续。
**Trigger**：景观、公共地面、展亭或半室外关系重要。
**Spatial Operation**：用部分墙面、屋盖、地面连续、视线或间隙建立阈值。
**适用边界**：气候与运营允许的公共、文化与景观型项目。
**Failure Mode**：忽略雨、风、热、烟控、安防与声学。
**可验证空间痕迹**：平面和剖面同时显示“哪里连续、哪里必须截断”。

## D09｜LIFE-SCENARIO CONFIGURATION｜生活场景配置
**判断含义**：空间配置必须回应真实使用者怎样共同生活 / 工作，而非抽象开放。
**Trigger**：用户关系、私密等级、家庭 / 团体活动模式已知。
**Spatial Operation**：把典型场景、冲突与转换写成空间状态。
**适用边界**：用户信息足够的住宅、社区、学习与工作空间。
**Failure Mode**：把单一家庭模型普遍化。
**可验证空间痕迹**：每个空间决策能指向已知用户场景；未知用户不得补写。

# DNA Selection Logic

- 默认 2–4 个。
- 至少一个 DNA 必须直接解决主空间冲突。
- D03 仅在真实时间 / 使用变化存在时启用。
- D05 仅在真实成本、采购、重复或装配条件存在时启用。
- D06 仅在身体尺度构件会改变房间关系时启用。
- D07 进入方案时必须同步做光环境验证。
- D08 进入方案时必须同步做气候 / 安防 / 消防 / 运营校正。
- D09 只有在用户场景有 KNOWN 证据时启用。
- 未选 DNA 不得在 A/B/C、Recommendation、Keep、Next、Prompt 或 Handoff 中回流。
