# 040｜Problem Route Runtime

> 以下为证据支持的**项目问题路线**，不是人为划定的生涯时期，也不声称历史斯特林有这些标准英文名称。
> 同一项目先选一个 PRIMARY Route；只有确有第二个不可归并冲突时，可记录 SECONDARY Route 供对比，但 Prompt 和最终推荐不自动继承它。

## R1 PROGRAM_PARTS｜多功能差异的组合
- Trigger：教育、研究、混合公共机构具有不同活动尺度、环境或开放权限。
- 核心问题：不同用法能否分别被看见并通过连接组织，而非被虚假单一体量掩盖？
- Method：功能矩阵→每部分空间需求→交界/服务/分隔→组合剖面。
- 主 DNA：D01, D02, D04。
- 边界：安全、使用频率、服务效率与预算优先于拼贴体量。
- 风险：复杂外形先行、交通距离增加、构造节点失控。
- 差异：着眼内部机构的分部与装配，不以穿越城市为主。
- Evidence：Pritzker 引用的 Stirling 本人 1979 文字；Leicester official heritage listing。

## R2 CULTURAL_TYPE｜文化机构的类型转译
- Trigger：图书馆、文化展馆、学术中心存在文化识别和公共仪式需要。
- 核心问题：哪一种熟悉的空间秩序能真正帮助到达、聚集、使用？
- Method：使用场景→历史类型的关系分析→删去非必要表象→改造为当代平剖空间。
- 主 DNA：D03, D04, D07。
- 边界：不可为“历史感”牺牲使用；无类型诉求则不启用。
- 风险：象征符号空转、历史引用被误读为授权复制。
- 差异：着眼历史与机构记忆，而非研究实验的工艺/光照。
- Evidence：Pritzker 1979 引文；CCA WZB 类型研究。

## R3 CITY_PASSAGE｜市民穿行与机构边界
- Trigger：城市公共建筑需协调两个城市界面、穿行需求和受控内部。
- 核心问题：公众经过与正式入馆能否分辨，同时保持真正可达、可管？
- Method：城市双端点→开放权限图→步行/无障碍双路径→机构入口/消防边界→运营时段。
- 主 DNA：D05, D06, D02。
- 边界：只有已核实的城市连接与合法开放条件才能形成公共穿越；否则降级为内部连接。
- 风险：公众路径依赖非开放楼宇、噪声安全冲突、坡道不可达。
- 差异：首要目标是城市连续性与门槛管理，不是内部功能分部。
- Evidence：Pritzker Stuttgart urban contextual consideration; 作为具体路线的普适化为 SUPPORTED INTERPRETATION，需要项目级测试。

## R4 LIGHT_WORK｜工作过程与环境表达
- Trigger：实验、制造、教学和复杂技术空间，环境需求对剖面有决定作用。
- 核心问题：环境与使用流程如何真实决定体量关系和采光剖面？
- Method：任务与工艺→自然光/眩光/通风/污染指标→剖面测试→工作与公共分离。
- 主 DNA：D01, D08, D04。
- 边界：高度依赖技术顾问及当代建筑物理验证。
- 风险：照搬历史的玻璃屋顶或斜线导致热工失败、维护高昂。
- 差异：由具体性能驱动而不是文化典故、城市穿越。
- Evidence：Historic England Leicester Engineering Building 的工坊北向采光说明。

## Route selection
1. 从项目 KNOWNS 标记触发条件，每条得分：触发冲突 (2) + 主功能对应 (1) + 有已知可落地条件 (1) - 关键条件 UNKNOWN (1)。
2. 最高且得分≥2 的路线优先；同分选择对核心用户/运营冲突解释力更强者并标为判断假设。
3. 没有路线满足时输出 ROUTE UNDETERMINED，并提出不超过三个关键问题，禁止为了填路线而硬选。
4. Secondary Route 只进入 A/B/C 候选比较且需要单独证据；正式推荐与 Prompt 只继承 Dominant Strategy 中**明确已选**的机制。
5. 每次改变路线需重新审核 DNA、Decision Rules 和 Prompt Fact Lock。
