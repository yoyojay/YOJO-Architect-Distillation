# 040｜Decision & Return Runtime

所有 Rule 必须明确：当 → 优先 → 因为 → 验证 → 失败回退。
这些 Rule 是基于 040 Method 的当代项目执行算法，不是历史建筑师亲述规则。

- **R-FACT**：当输入含未经核实的几何、材料、城市边界 → 优先标 UNKNOWN/NEED VERIFY → 因为错误事实会污染设计链 → 验证资料来源与业主确认 → 失败则停用该具体假设。
- **R-FIT**：当缺少多元功能/文化机构/城市关系/环境过程等方法触发 → 优先 PARTIAL/NOT FIT → 因为形象相似不是项目匹配 → 验证核心冲突是否能被 Route 解释 → 失败则建议通用功能与合规分析而非勉强 Stirling 化。
- **R-ROUTE**：当多功能内部组织是真正主问题 → 优先 R1 而非 R3 → 因为要先明确功能块关系 → 验证邻接/人流/服务图 → 失败重选路线。
- **R-TYPE**：当历史记忆有可说明的空间意义 → 优先类型关系转译而非外观引用 → 因为旧类型的空间逻辑可用于当前使用 → 验证现代平面/剖面能否独立成立 → 失败移除类型层。
- **R-DNA**：当 DNA 无触发或可见痕迹 → 优先不选 → 因为完整性不等于堆功能 → 验证 Plan/Section/Movement Trace → 失败取消 DNA 并刷新策略。
- **R-STRATEGY**：当 A/B/C 只有材料或形式区别 → 优先重新做三套因果不同的组织假设 → 因为形式不同不是解法不同 → 验证每案主导问题、路径和分区实质不同 → 失败停止比较。
- **R-MOVEMENT**：当公共路线在剖面中不可达或与后台冲突 → 优先真实无障碍与运行边界 → 因为可达性是路线成立条件 → 验证全流程动线/门禁/消防 → 失败退回路径/机构边界关系。
- **R-PERFORMANCE**：当采光剖面导致热负荷、眩光或维护风险 → 优先物理性能修正 → 因为历史项目有具体负面教训 → 验证顾问报告与方案指标 → 失败取消象征性顶棚。
- **R-RECOMMEND**：当一个方案可独立解决核心冲突 → 优先单一 Dominant；仅在严格必要时借一机制 → 因为三案混合会破坏验证 → 通过机制隔离表检查 → 失败重新推荐且删除所有回流项。
- **R-CRITIC**：当既有方案只有历史符号/效果图强效果 → 优先检验实际使用与工程 → 因为“风格正确”非实证 → 验证图纸、模拟与可达动线 → 失败标 REJECT 或 CORRECT。
- **R-RETURN**：当 Route/DNA/Recommendation/Prompt Fact Lock 任一不通过 → 优先回上一个正确因果层 → 因为再画效果图不能修逻辑 → 指明回退到 Input/Route/Strategy 的节点 → 再审直至合格。
