# AR77-010｜Decision Rules Runtime

## Fact Lock
When a project fact is missing → keep it UNKNOWN / NEED VERIFY → because invented specificity corrupts downstream reasoning → verify through user/project documents → if unresolved, use relation/performance language.

## Fit
When the dominant problem is spatial order, adaptability, boundary relation or larger site order → test FIT → because the Method has supported mechanisms there → verify against project conflicts → if privacy/code/operations dominate against openness, downgrade to PARTIAL FIT or NOT FIT.

## Route
When one conflict clearly governs the project → select one Primary Route → because routing stabilizes causal reasoning → verify that its Trigger and Boundary match → if not, return to Route Selection.

## DNA
When a DNA does not solve a named conflict → exclude it → because mechanism stacking causes style imitation → verify through a plan/section trace → if no trace exists, remove it.

## Strategy
When A/B/C differ only by image/material/degree → FAIL → because strategy difference must be causal → verify which system carries order in each strategy → if the answer is the same, regenerate.

## Plan–Section–Movement
When a strategy is described verbally → require a plan, section and movement consequence → because Miesian order must be spatially legible → verify through 1–3 diagrams → if one layer contradicts another, return to Method.

## Performance
When openness or boundary continuity conflicts with climate/fire/acoustics/privacy/operations → prioritize contemporary performance → because historical precedent does not waive current obligations → verify with appropriate professional test → if unresolved, mark NEED VERIFY.

## Recommendation
When one strategy resolves the dominant conflict best → make it Dominant → because recommendation is a decision, not a collage → verify it works independently → if it requires mechanisms from both other strategies, return to Comparison.

## Critic
When a scheme looks visually “Miesian” but its structure/space relation is weak → reject the style evidence → because image is not Method → verify actual plan/section/system causality → if absent, return to Method.

## Failure Return
When Prompt Fact Lock finds unsupported material/structure/façade/geometry → delete or generalize → because visual specificity cannot outrun facts → verify traceability → if still unsupported, do not output it.
