# AR77-037｜DECISION RULES

1. **当**先出现贝壳 / 云 / 波浪曲面 → **优先** D01 + D06 → **因为**自然启发必须转成生成 / 构造规律 → **通过** site / geometry / engineering trace 验证 → **失败则**删除轮廓。
2. **当**提出大平台 / 大台阶 → **优先** R1 + D02 → **因为**平台必须解决真实主次功能 / 场地 / 到达 → **通过** section + accessibility + service routes → **失败则**退回连续地面。
3. **当**住宅要 community + privacy → **优先** R2 + D03 → **因为**院落必须同时解决生活与微气候 → **通过** privacy/sun/wind/shared-path → **失败则**不用院落套路。
4. **当**说“可扩展 / 模块化” → **优先** R3 + D04 → **因为**additive architecture 必须有增长 / 构件经济 → **通过** phase + interface + MEP/fire → **失败则**取消模块系统。
5. **当**宗教 / 文化空间想要特殊屋顶 → **优先** R4 → **因为**屋顶首先组织光、声学、集体空间与结构 → **通过** section/daylight/acoustic/structure → **失败则**不得补 cloud/shell 形象。
6. **当**路径过度戏剧化 → **优先** D05 → **因为**路径应服务活动 / 场所 → **通过** movement + accessibility + wayfinding → **失败则**简化。
7. **当**住宅场地非常具体 → **优先** R5 + D07 → **因为**房间应围绕生活事件与现场校正 → **通过** event + view/sun/wind plan-section → **失败则**不复制 Can Lis。
8. **当**自动选择当地材料 / 预制 → **优先** D08 → **因为**材料 / 构件必须有供应、工艺、成本事实 → **通过** procurement + mock-up → **失败则**改成性能要求。
9. **当** A/B/C 只是三种屋顶 / 材料 / 曲率 → **优先**重做 → **因为**策略必须因果不同 → **通过**不同 primary causal mechanism → **失败则**Strategy Gate FAIL。
10. **当** Recommendation 想合并三案 → **优先**只留一个 Dominant → **因为**Dominant 必须独立成立 → **通过**最多一个 Borrowed Mechanism → **失败则**Recommendation Gate FAIL。
11. **当** Prompt 自动补 white tile / stone / timber / concrete / shell / courtyard / monumental steps → **优先** Prompt Fact Lock → **因为**历史项目特征不是当前事实 → **通过** KNOWN / selected Route / Dominant / Borrowed / Selected DNA / verified site-climate-light 追溯 → **失败则**删除 / 泛化。
12. **当** Sydney 结构被写成 Utzon 单独完成 → **优先** Collaboration Boundary → **因为**几何与工程实现经过 Utzon + Arup teams 协同演化 → **通过**来源归属验证 → **失败则**改写为协作成果。
