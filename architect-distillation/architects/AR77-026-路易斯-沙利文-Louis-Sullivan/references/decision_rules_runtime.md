# Decision Rules
1. 当用户引用“form follows function” → 优先列出真实功能角色 → 因为口号不能替代判断 → 通过平面/剖面/路径验证 → 若形式与功能无因果则回退。
2. 当高层出现大量重复层 → 优先建立 whole-before-part + repetition logic → 因为类型整体不能是楼层堆叠 → 通过典型层/整体立面/剖面验证 → 失败则重组构成。
3. 当需要 ornament → 优先定义其整体任务和生成规则 → 因为 Sullivan 的 ornament 不是贴附 → 通过整体—局部 trace 验证 → 无任务则删除。
4. 当外部竖向表达被提出 → 优先检查真实结构/重复/高度关系 → 因为表达不能伪造功能 → 通过结构—围护剖面验证 → 无支持则取消。
5. 当首层需要更强识别 → 优先解决街道、入口、展示和人尺度 → 因为公共界面来自使用 → 通过 ground-floor plan + pedestrian sequence 验证 → 失败则重做 threshold。
6. 当推荐形成 → 只保留一个 Dominant + 最多一个有限 Borrow → 因为整体观念必须一致 → 通过 function/form/whole-part 四项一致性验证 → 失败返回 Route。
