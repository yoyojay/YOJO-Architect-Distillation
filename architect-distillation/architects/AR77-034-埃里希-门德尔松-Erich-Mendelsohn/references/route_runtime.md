# AR77-034｜PROBLEM ROUTES
## Erich Mendelsohn｜Project-Problem Routing

这些 Route 是 AR77 从证据中建立的 **项目问题路由**，不是历史阶段，也不是 Mendelsohn 本人命名的分类。

---

## R1｜TECHNICAL_INSTRUMENT_SYNTHESIS｜技术仪器整合

**Trigger**
- 核心设备 / 仪器 / 生产过程决定空间；
- 振动、精度、维护、结构或环境控制是主要生成条件。

**核心问题**
如何把严格技术依赖转成建筑空间，而不是把技术藏进一个任意造型外壳。

**Method**
设备 /过程需求 → 独立支撑 / 结构 / 服务关系 → 维护路径 → 工作空间 → 外部体量与光的表达。

**主要 DNA**
D01 / D02 / D05 / D03

**适用边界**
实验、科研、制造、设备密集型文化 / 公共设施。

**风险**
设备更新、振动、热、检修、防火、结构与表达冲突。

**与其他 Route 差异**
它由精确技术依存关系驱动，而不是城市可见性或公共集会驱动。

---

## R2｜URBAN_COMMERCE_VISIBILITY｜城市商业 / 可见性

**Trigger**
- 商业、展陈、公共服务与街道关系是主问题；
- 顾客路径、展示、日夜运营、街角识别显著影响项目。

**核心问题**
如何把人流、展示、光与城市界面组织为同一系统，而不是附加“动感立面”。

**Method**
到达与客流 → 展示 / 开放层 → 日光 + 人工照明需求 → 街道 / 转角可见性 → 服务与后勤 → 外部表达。

**主要 DNA**
D01 / D04 / D06 / D03 / D09

**适用边界**
商业、零售、展陈、城市综合公共界面。

**风险**
眩光、光污染、能耗、广告法规、货运与客流冲突、夜间安全。

**与其他 Route 差异**
它由城市运营与可见性驱动。

---

## R3｜DYNAMIC_PUBLIC_SEQUENCE｜动态公共序列

**Trigger**
- 到达、楼梯、门厅、集会、露台 / 公共空间之间的序列是体验核心；
- 同一项目含多个公共活动，路径需要成为空间组织器。

**核心问题**
如何把运动和停留转成平剖关系，而不是用曲线表达“速度”。

**Method**
关键事件节点 → 路径速度 / 停留 → 方向变化 → 剖面连接 → 光与视线 → 集会空间。

**主要 DNA**
D01 / D03 / D04 / D06

**适用边界**
文化、公共、交通关联、娱乐与大型集会项目。

**风险**
无障碍、疏散、拥堵、导向、声学、运营分区。

**与其他 Route 差异**
它由身体路径和公共序列驱动；De La Warr Pavilion 仅作为合作项目的佐证，不作为可复制构图。

---

## R4｜CLIMATE_CONTEXT_TRANSLATION｜气候 / 场所转译

**Trigger**
- 气候、地形、朝向、风、文化环境或材料供应显著不同于用户预设的现代建筑语言。

**核心问题**
如何让现代组织原则随场所改变，而不是搬运欧洲 1920s 的形式。

**Method**
场地 / 气候事实 → 日照 / 风 /热 / 雨 → 室内外关系 → 朝向 / 庭院 / 遮护等关系策略 → 当地施工与文化边界 → 形式。

**主要 DNA**
D01 / D07 / D03 / D09

**适用边界**
住宅、机构、校园、气候敏感公共建筑。

**风险**
把“地方性”简化成历史符号；未经验证自动补庭院、水体、石材或深檐。

**与其他 Route 差异**
它由场所与气候差异驱动。

---

## R5｜FLEXIBLE_COMMUNITY_ASSEMBLY｜可变社区集会

**Trigger**
- 同一场所服务不同人数、仪式、教育、社交或社区活动；
- 高峰容量与日常容量差异显著。

**核心问题**
如何在保持空间整体性的同时，让容量与活动状态变化。

**Method**
活动 / 容量矩阵 → 固定核心 → 可变边界 / 可扩展区域 → 声学 / 视线 → 疏散 / MEP → 日常运营。

**主要 DNA**
D01 / D08 / D04 / D09

**适用边界**
宗教、社区、教育、会议、文化与混合集会项目。

**风险**
移动边界声学不足、消防失败、设备覆盖不一致、切换成本过高。

**与其他 Route 差异**
它由容量与活动模式变化驱动，不以“动态形象”为目标。

---

# Route Selection Logic

1. 先写主冲突，再选 Route。
2. Primary Route exactly 1。
3. Secondary Route = NONE 或最多 1 个。
4. Secondary 必须解决另一个真实冲突，不能只是为了让方案更“丰富”。
5. R1 只有在技术 / 仪器真正主导时启用。
6. R2 只有在城市可见性 / 商业流线真实重要时启用。
7. R4 只能依据 VERIFIED site / climate / cultural constraints，不能自动补地方元素。
8. R5 只有容量 /活动切换为 KNOWN 时启用。
9. 未选 Route 不得进入 Recommendation / Prompt / Handoff。
10. 若 Route 选择只是为了复制某个 Mendelsohn 代表作，Route Selection FAIL。
