# AR77-034｜DECISION RULES

1. **当**出现曲面、圆角、横向窗带，但无法说明用途 /材料 /结构依存  
   **→ 优先**回到 D01  
   **→ 因为**Mendelsohn 的“动态”不是造型标签  
   **→ 通过**Plan / Section / system dependency 验证  
   **→ 若失败则**删除该形式。

2. **当**技术 /仪器是主条件  
   **→ 优先**R1 + D02 / D05  
   **→ 因为**技术依赖应先生成结构与维护关系  
   **→ 通过**设备—结构—维护—人员剖面验证  
   **→ 若失败则**退回 NEED VERIFY，不生成具体技术形式。

3. **当**商业 /城市可见性是主问题  
   **→ 优先**R2 + D06  
   **→ 因为**界面应服务人流、展示与日夜运营  
   **→ 通过**day/night + arrival + ground-floor plan 验证  
   **→ 若失败则**删除发光、窗带、转角等视觉主张。

4. **当**用户要求“动感建筑”  
   **→ 优先**D03  
   **→ 因为**动态必须来自方向、时间、体量、光或运动关系  
   **→ 通过**movement / section / time-state diagram 验证  
   **→ 若失败则**禁止用曲线代替因果。

5. **当**公共路径是项目核心  
   **→ 优先**R3 + D04  
   **→ 因为**运动应改变空间节点和剖面  
   **→ 通过**连续 plan-section route 验证  
   **→ 若失败则**路径只算导向，不算空间机制。

6. **当**气候 /场所与先入形式冲突  
   **→ 优先**R4 + D07  
   **→ 因为**Mendelsohn 在不同地域改变输出  
   **→ 通过**orientation / sun / wind / rain / thermal evidence 验证  
   **→ 若失败则**不得自动补庭院、水体、石材或地方符号。

7. **当**同一集会空间需要多种容量  
   **→ 优先**R5 + D08  
   **→ 因为**空间变化应服务真实活动规模  
   **→ 通过**至少两种状态的消防 /声学 /MEP /运营验证  
   **→ 若失败则**改用稳定容量策略。

8. **当**光被用于建筑表达  
   **→ 优先**确认它同时满足视觉、热、运营与安全  
   **→ 因为**光是空间要素而非“发光效果”  
   **→ 通过**daylight / glare / night-lighting / energy test 验证  
   **→ 若失败则**改写为性能语言。

9. **当**A/B/C 只是曲线强弱、窗带多少或材料变化  
   **→ 优先**重做三案  
   **→ 因为**策略必须因果不同  
   **→ 通过**每案不同 Primary causal mechanism 验证  
   **→ 若失败则**Strategy Gate FAIL。

10. **当**Recommendation 想吸收 A+B+C  
    **→ 优先**只保留一个 Dominant  
    **→ 因为**Dominant 必须独立成立  
    **→ 通过**最多一个 Borrowed Mechanism 验证  
    **→ 若失败则**Recommendation Gate FAIL。

11. **当**Prompt 想补材料、结构、曲率、窗型、屋顶、照明或家具  
    **→ 优先**Prompt Fact Lock  
    **→ 因为**视觉完整度不能替代事实  
    **→ 通过**KNOWN / selected Route / Dominant / Borrowed / Selected DNA / verified site-climate-light 追溯  
    **→ 若失败则**删除或泛化。

12. **当**Scheme Critic 中 Selected DNA 找不到 plan / section / movement / system / operation 痕迹  
    **→ 优先**判定该 DNA 未成立  
    **→ 因为**DNA 是可验证机制，不是文案  
    **→ 通过**图纸 /状态 /系统证据验证  
    **→ 若失败则**删除 DNA 或返回策略重做。
