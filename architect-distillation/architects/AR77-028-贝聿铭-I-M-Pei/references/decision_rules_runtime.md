# Decision Rules
1. 当场地异常 → 优先提取不可回避限制 → 因为几何应从问题生成 → 通过 constraint-to-order diagram 验证 → 若几何不能改善组织则删除。
2. 当用户先指定 triangle/pyramid → 优先回到 site/use/circulation → 因为几何不是签名 → 通过至少两种组织方案比较 → 无优势则不用。
3. 当公共建筑难定向 → 优先建立 arrival-orientation-branch-return → 因为人的理解先于视觉奇观 → 通过 circulation test 验证 → 失败则重组中心/路径。
4. 当新建筑进入历史环境 → 优先拆分 scale/alignment/view/material 等关系 → 因为尊重不等于模仿 → 通过 old-new comparison 验证 → 失败则调整介入。
5. 当自然光成为概念 → 优先验证方位、用途、保护、眩光、热 → 因为光必须可使用 → 通过 daylight/thermal section 验证 → 失败则改剖面/边界。
6. 当推荐形成 → 只保留一个 Dominant + 最多一个有限 Borrow → 因为 governing order 必须清晰 → 通过 Plan/Section/Movement/Context 一致性验证 → 失败返回 Route。
