# AR77-013｜DECISION RULES

1. **Fact Lock**  
当关键事实未知 → 保持 UNKNOWN / NEED VERIFY → 因为具体化会污染后续判断 → 通过输入追溯验证 → 若不可验证则泛化或删除。

2. **Fit**  
当项目真正需要关系、三维迭代、差异化组织或专业系统协同 → 才使用本 Kernel → 因为 Fit 来自问题而非“雕塑感” → 通过冲突定义验证 → 若只能靠 Gehry-like image 成立则 NOT FIT。

3. **Route**  
当一个冲突主导项目 → 选择一个 Primary Route → 因为路由必须保持因果清晰 → 通过 Core Question 验证 → 若两条同等主导则重新定义冲突。

4. **DNA**  
当 Route 已选 → 只选解决冲突所需 3–5 DNA → 因为未选机制会造成回流 → 通过 drawing/model/test trace 验证 → 无痕迹 DNA 删除。

5. **Model Test**  
当几何、体量、空间或移动存在三维不确定性 → 先建立可比较模型 → 因为模型应回答问题而非制造造型 → 通过 alternative + criterion 验证 → 若模型没有改变判断则降低其优先级。

6. **Strategy**  
当生成 A/B/C → 每套必须有不同 Core Cause → 因为策略差异必须是因果差异 → 通过至少两项 plan/section/movement/model 改变验证 → 只换皮肤/曲率/材料则 FAIL。

7. **Plan–Section–Movement**  
当提出复杂体量 → 必须说明平面、剖面、路径至少两项如何改变 → 因为轮廓不是空间证据 → 通过图纸/模型验证 → 若只有外壳语言则返回 Route/DNA。

8. **Performance**  
当几何或专业性能成为关键 → 尽早引入结构/MEP/声学/幕墙/施工验证 → 因为数字可描述不等于可建、可用、可维护 → 若失败则修改几何或策略。

9. **Recommendation**  
当比较完成 → 选择 one Dominant + at most one bounded Borrowed Mechanism → 因为推荐必须可独立成立 → 通过删除其他策略后仍完整验证 → 若必须三套混合则重新比较。

10. **Critic**  
当审查现有方案 → 先查 people/program/context/model evidence → 再查视觉强度 → 因为强效果图可能掩盖未解决关系 → 若因果不成立则返回 conflict。

11. **Failure Return**  
当模型、性能或运营测试失败 → 返回 conflict/Route/DNA/strategy → 因为失败应修正判断链 → 禁止用更复杂曲面或更强材质效果补救。
