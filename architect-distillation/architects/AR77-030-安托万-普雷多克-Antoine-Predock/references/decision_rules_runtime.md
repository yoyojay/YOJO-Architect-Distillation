# AR77-030｜Decision Rules Runtime

每条规则遵循：
`当… → 优先… → 因为… → 通过…验证 → 若失败则…`

## R01｜Fact Lock
当项目事实缺失 → 优先标记 UNKNOWN / NEED VERIFY → 因为 Predock 方法依赖真实场所线索 → 通过输入表与资料核对 → 若失败则只问下一轮 1–3 个关键问题。

## R02｜Fit
当项目允许场所、身体移动或公共领域成为空间因果 → 优先 FIT / PARTIAL FIT 判断 → 因为该 Method 不是独立于场地的造型语言 → 通过至少一个可验证 Route Trigger → 若没有 Trigger 则 NOT FIT，不强套。

## R03｜Route
当多个问题同时出现 → 优先选择 1 个 Primary Route → 因为项目需要清楚主因 → 通过“哪一个冲突若不解决项目就失败”判断 → 若仍并列，只允许 1 个 Secondary Route 提供单一机制。

## R04｜DNA
当 Route 确定 → 优先只选 2–4 个 DNA → 因为机制过多会把方法变成风格清单 → 通过每个 DNA 是否解决具体问题验证 → 若不能指向问题，删除。

## R05｜Climate Before Metaphor
当气候、雨水、热或风是关键风险 → 优先 D02 与性能测试 → 因为环境力应是事实而不是诗意叙述 → 通过日照/风/排水/热环境验证 → 若性能不成立，修改空间动作，不保留比喻。

## R06｜Movement
当路径成为主要机制 → 优先同时画平面 + 剖面 + movement sequence → 因为“旅程”必须被真实身体经历 → 通过长度、坡度、节点、可达性、导航与疏散验证 → 若失败，缩短或重构路径。

## R07｜Memory
当历史/文化/原住民/纪念内容进入设计 → 优先验证真实来源与相关群体意见 → 因为象征不能由建筑师自行替代社区意义 → 通过资料与利益相关者确认 → 若失败，撤回象征性叙事，保留中性空间关系。

## R08｜Strategy
当生成 A/B/C → 优先三个不同主因 → 因为三案必须测试不同空间因果 → 通过 Dominant Route / primary DNA / plan-section-movement 差异验证 → 若仅是材料、几何或强弱不同，重做。

## R09｜Performance
当策略产生复杂几何、长跨、巨型中庭或强地景动作 → 优先结构、消防、MEP、声学、维护、成本与生命周期校正 → 因为形式后置且必须可实施 → 通过专业顾问验证 → 若失败，修改策略而非用视觉理由保留。

## R10｜Recommendation
当比较完成 → 优先一个 Dominant Strategy，最多借一个有限机制 → 因为推荐必须保持可执行因果 → 通过正向策略计数 ≤ 2 验证 → 若 A+B+C 全部正向出现，HARD FAIL 并重写。

## R11｜Critic
当审查已有方案 → 优先追问“每个强形式由什么证据产生” → 因为 Predock 的外观不能被倒推成方法 → 通过 Route / DNA / 平剖路径 / 性能痕迹验证 → 若无法追溯，判为形式先行并退回问题定义。

## R12｜Failure Return
当任一关键机制不能通过空间或性能验证 → 优先返回最近的有效决策层 → 因为错误不应被后续视觉包装掩盖 → Route 错则回 Route；DNA 错则回 Selection；Strategy 错则重做 A/B/C；Prompt 错则只重写 Prompt，不擅自改 Method Kernel。
