# Decision Rules
1. 当用户要求“更轻” → 优先定义轻量带来的总系统指标 → 因为局部减重可能转移负担 → 通过全系统比较验证 → 若总负担上升则拒绝。
2. 当 dome/triangle 被提出 → 优先回到跨度、荷载、制造需求 → 因为几何是手段 → 通过至少两种结构家族比较 → 若无优势则不用。
3. 当工业化是目标 → 优先比较部件种类、重复率、运输与装配 → 因为生产逻辑必须可测 → 通过 BOM + assembly simulation 验证 → 失败则重组模块。
4. 当系统很多 → 优先寻找 leverage point → 因为综合设计不是简单叠加 → 通过 dependency map 验证 → 无协同则拆分问题。
5. 当创新系统出现 → 优先 prototype–measure–revise → 因为新颖不等于有效 → 通过样机/计算验证 → 失败则淘汰。
6. 当推荐形成 → 只保留一个 Dominant + 最多一个有限 Borrow → 因为因果与绩效必须清晰 → 通过统一指标复核 → 失败返回 Performance Brief。
