# Design DNA Runtime
默认选择 3–5 个必要 DNA；未选不得回流。

## D1｜Comprehensive System Boundary
判断: 先定义问题系统而非孤立建筑对象。
Trigger: 多专业冲突。
Operation: 画资源—结构—环境—使用—制造关系图。
边界: 系统边界必须可管理。
Failure: 无限扩张问题。
痕迹: 每个主要决策可指出影响的子系统。

## D2｜Performance per Resource
判断: 用单位资源的有效产出比较方案。
Trigger: 重量/材料/能源/成本受限。
Operation: 建 baseline 和比较指标。
边界: 指标必须包含转移成本。
Failure: 单指标极端优化。
痕迹: 可比较表。

## D3｜Geometry as Structural Information
判断: 几何用于组织力与构件关系。
Trigger: 大跨/轻量。
Operation: 比较多种结构几何。
边界: 不预设三角/球面。
Failure: 几何符号化。
痕迹: 几何变化对应结构性能变化。

## D4｜Prototype–Measure–Revise
判断: 原型用于证伪和修正。
Trigger: 新系统/非标准构造。
Operation: 物理或数字样机+测量。
边界: 每轮有明确变量。
Failure: 展示模型。
痕迹: 测试结果导致版本改变。

## D5｜Synergy over Local Optimization
判断: 优先寻找多系统共同受益。
Trigger: 一个优化导致另一系统恶化。
Operation: 建 dependency map，寻找 leverage point。
边界: 协同必须量化或明确验证。
Failure: 空泛“整体性”。
痕迹: 同一动作改善至少两个已定义指标且无隐藏转移。

## D6｜Industrial Part Logic
判断: 构件数量、重复率、制造与装配参与空间决策。
Trigger: 批量/快速部署。
Operation: part family + connection + packing matrix。
边界: 地方供应链优先验证。
Failure: 过度专利化部件。
痕迹: BOM/装配顺序清晰。

## D7｜Mobility / Reversibility
判断: 运输、拆卸、替换可能成为生命周期性能。
Trigger: 临时/可迁移/循环项目。
Operation: dry connections / disassembly sequence as relationship language.
边界: 不自动指定连接技术。
Failure: 可拆卸只停留口号。
痕迹: 可逆顺序与替换单元明确。

## D8｜Anticipatory Scenario Testing
判断: 设计要测试未来变化而非只满足静态瞬间。
Trigger: 使用、气候、部署规模存在不确定性。
Operation: 建多个情景并测试系统弹性。
边界: 不预测不可知未来。
Failure: 技术乌托邦。
痕迹: 方案在至少两个合理情景下有可解释响应。
