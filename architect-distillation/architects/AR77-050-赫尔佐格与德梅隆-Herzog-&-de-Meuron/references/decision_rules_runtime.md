# AR77-050｜DECISION RULES / SELECTION + FAILURE RETURN
## Jacques Herzog & Pierre de Meuron

规则遵循：`当… → 优先… → 因为… → 通过…验证 → 若失败则…`。

1. **Fact Lock**：当信息只来自案例联想或模型猜测 → 优先将其标为 NEED VERIFY → 因为当前项目事实不能从名作继承 → 用用户资料 / 测绘 / 专业测试验证 → 无证据则删除具体陈述。
2. **Fit**：当用户要求“像鸟巢 / Tate / 石笼墙”但项目不含相应问题 → 优先 NOT FIT 风格模仿、改问真实项目冲突 → 因为共同实践不是形式套装 → 用用户诉求和项目 brief 验证 → 若无冲突，不继续形式生成。
3. **Route**：当存在可利用遗存与新功能冲突 → 优先 R1 → 因为旧结构与大空间可能构成再编程潜能 → 通过 existing / new overlay + feasibility 验证 → 不可行则离开 R1，不编造“工业遗产精神”。
4. **Route**：当围护性能是主矛盾 → 优先 R2 → 因为材料选择必须同时处理热、光与实际装配 → 通过 climate data / section / assembly test → 不达标改选朴素且合规的围护。
5. **Route**：当项目有授权艺术内容或空间传播问题 → 优先 R3 → 因为表面图像应与体量空间互相改变 → 通过版权 / view test / daylight / cost → 若失败则去图像层。
6. **Route**：当有真实 civic event + everyday public use → 优先 R4 → 因为文化地标必须是可用公共设施 → 通过 crowd + ticket/security/accessibility + normal/night plan → 不成立则下调“公共平台”主张。
7. **Route**：当长期照护与生活体验冲突 → 优先 R5 → 因为患者 / 家属 / 员工真实活动必须先于机构造型 → 通过医护流程及患者代表 / 无障碍 / 感染控制验证 → 失败即返回专业运营方案。
8. **DNA Selection**：当更多 DNA 被选只是为了“丰富” → 优先 D01 + 2–3 个真正必要机制 → 因为每项必须解决不同冲突 → 用 Trigger + Observable Trace 检查 → 失败删除；UNSELECTED 永不回流。
9. **Material**：当材料被称“有 Herzog & de Meuron 质感” → 优先识别它能解决的 boundary / thermal / sensory / craft 问题 → 因为材料并非签名 → 用 mock-up / performance / supply chain 验证 → 失败删除或改中性表达。
10. **Prototype**：当有新型表皮孔隙 / 非标装配 → 优先 D05 → 因为图像无法证明制造 / 维护 / 火性能 → 通过 full-scale bay 与数字模拟 / 检测交叉验证 → 不可行则取消复杂构件。
11. **Image / Collaboration**：当图像、艺术家或结构工程决定空间 → 优先 D06 / D09 且保留贡献者姓名与权利 → 因为设计不是二人独作每个系统 → 用 source / contracts / consultant sign-offs 验证 → 失败撤去未授权成分。
12. **Plan-Section-Movement**：当概念只在立面效果图成立 → 优先回到平面、剖面、步行路径与房间体验 → 因为身体 / 使用必须可追溯 → 用 eye-level / section / service path 验证 → 失败重做 A/B/C。
13. **Strategy**：当 A/B/C 只换石材、金属网、图像、强弱或表皮 → 优先重新定义互不相同的 causal drivers → 因为策略必须因果不同 → 用 route / DNA + plan/section/performance 对照 → 失败 Strategy Gate FAIL。
14. **Performance**：当透光 / 隔热 / 声学 / sustainability 被宣称已成立 → 优先专业模拟 / 实测与本地 code → 因为旧项目技术结果不可直接迁移 → 用 measurable targets → 失败则标 Need Verify，不许写已验证。
15. **Recommendation**：当想把 A+B+C 全部拼入 → 优先一个独立可成立的 Dominant → 因为选定策略必须能归因 → 用 Borrowed ≤1 from one other strategy + Rejected no reentry 审计 → 失败则回退 Recommendation。
16. **Critic**：当方案被“强效果图”冻结 → 优先追踪 Method / Route / Selected DNA / geometry / plan-section-movement / performance → 因为视觉不能成为设计事实 → 用 fail / revise / retest 表 → 失败回到 Project Conflicts。
17. **Prompt Fact Lock**：当 Prompt 生成 mesh / concrete / basalt / brick / photo print / glazing / roof / furniture → 优先逐项追溯 KNOWN / selected Route-Method / Dominant / one Borrowed / Selected DNA / verified site-climate-light → 若不可追溯，删除或改写为关系 / 性能语言。
18. **Professional Boundary**：当方案触及结构、消防、声学、医疗、制造、许可或公共治理 → 优先独立专业和利益相关者核查 → 因为 Architect Skill 不能取代执业责任 → 使用有签名的测试 / 批准 → 未通过不得承诺建造或治愈效果。
