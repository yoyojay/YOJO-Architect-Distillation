# SINGLE IMAGE VISUAL HANDOFF
## AR77-050｜Jacques Herzog & Pierre de Meuron

### Product Role
把已确认的建筑判断交给**单张**概念视觉验证，不是完整视觉生产系统，不负责从图像倒推出新设计事实。

### Activation Gate
四项必须同时成立：
1. 已完成当前项目 AR77-050 分析；
2. 用户已经**明确确认 Dominant Strategy**；
3. Selected Route / Selected DNA 和 KNOWN facts 已锁定；
4. 用户明确要求单张概念视觉验证。

任一缺失：STOP 并只问最多 1–3 个关键确认问题，不能把草案当确认稿。

### Input Inheritance Contract
只继承：
- confirmed KNOWN project facts；
- confirmed Method / selected Route；
- **one** confirmed Dominant Strategy；
- optional **one** Borrowed Mechanism from one other strategy；
- Selected DNA；
- verified site / climate / light；
- existing Prompt Fact Lock。

禁止新增：
- 未指定材料、结构、表皮、形式、屋顶、柱网、艺术图像、家具、景观；
- Rejected Strategy、unselected Route、unselected DNA；
- “Herzog & de Meuron style”、代表作或建筑师名称作为视觉风格词；
- 鸟巢网架、石笼、印花混凝土、夯土、铜板、波浪玻璃、晶体外形的自动补写。

## 01｜Confirmed Strategy
写 Dominant ID、因果理由、confirmed optional Borrowed（否则 NONE）。

## 02｜Route / Method Trace
写一条从用户真实空间冲突到**已确认**空间操作的证据链。

## 03｜Selected DNA
列选中 ID、触发与必要 observable trace，未选不得列入。

## 04｜Spatial Locks
必须在图中可见的真实 Plan / Section / Movement / Envelope / Public Use 关系；只用已有确认信息。未知材料仍保持中性关系表达。

## 05｜Must Not Drift
- 不把旧名作当作新项目的视觉答案；
- 不新增未经验证的材料、结构、开口或形体；
- 不把艺术家 / 工程师的具体成果移植为随意签名；
- 不补救不了的气候、可达、公共运营问题；
- 不复活 Rejected 或未选机制。

## 06｜Single Demonstration Image Prompt
描述：
`confirmed project type + real user activity + confirmed site / climate / light + confirmed route / method + Dominant Strategy + max one Borrowed + Selected DNA + spatially informative viewpoint`。
只要求一张具有合理身体尺度和空间因果的概念验证视角；不强制某种材料或形式，不写名作名或 X style。

## 07｜Negative Constraints
只列当前策略相关、已经检查的反向约束，例如 `no unconfirmed mesh/gabion/printed facade/extra public plaza`，不新增设计对象。

## 08｜Handoff Note
> 这是一张对已确认建筑判断的概念验证图，不是新的设计事实，也不代表施工或专业性能已获认证。
