# AR77-029 Álvaro Siza｜Decision Rules

## RULE-01｜Fact Lock
当项目信息未被用户明确提供或可靠验证 → 标为 UNKNOWN / NEED VERIFY → 因为西扎方法依赖真实处境而不是补全想象 → 通过输入清单验证 → 若关键事实缺失，只问下一批 1–3 个问题。

## RULE-02｜Fit
当项目允许从场地、既有、路径、城市连续、房间差异或多方协商中形成空间判断 → 优先 FIT / PARTIAL FIT → 因为方法依赖具体问题转化 → 通过是否存在可操作现实条件验证 → 若项目只要求复制外观，判 NOT FIT。

## RULE-03｜Route
当一个冲突明显支配其他问题 → 只设一个 Primary Route → 因为项目差异来自问题与地点 → 通过 Trigger + Project Evidence 验证 → 若证据不足，Route = NEED VERIFY。

## RULE-04｜DNA
当 Route 已确定 → 选择最小充分 DNA 集 → 因为不是完整词汇库堆叠 → 通过每条 DNA 的独立 Trigger 与可验证痕迹检查 → 若重复解释同一问题，删除冗余 DNA。

## RULE-05｜Strategy
当生成 A/B/C → 三案必须采用不同 Primary Cause → 因为真正差异应来自空间因果而不是外形 → 通过 Cause / Plan / Section / Movement 四项对照 → 若仅材料或形状不同，全部重做。

## RULE-06｜Plan–Section–Movement
当方案提出关键空间动作 → 必须同时解释它怎样改变平面、剖面与运动 → 因为路径和场地关系不能只存在于叙述 → 通过三图逻辑闭环验证 → 若任一维度无痕迹，策略降级或返工。

## RULE-07｜Performance
当路径、开口、房间或地形操作带来体验收益 → 同时检查 accessibility / fire / climate / acoustics / privacy / operations / structure / MEP → 因为方法必须进入当代项目 → 通过专业 Need Verify 清单验证 → 若性能矛盾无法解决，修改空间动作而非强保形式。

## RULE-08｜Recommendation
当三案比较完成 → 选择一个可独立成立的 Dominant Strategy；最多借另一案一个有限机制 → 因为推荐必须保持因果清晰 → 通过 Positive Strategy Count ≤ 2 验证 → 若第三策略回流，重新推荐。

## RULE-09｜Critic
当用户提供已有方案 → 先判断它是否真的从条件转化而来，再检查 Route / Selected DNA / plan-section-movement / performance → 因为效果图不能替代方法成立 → 通过 KEEP / CORRECT / REJECT 逐项验证 → 若只剩“像西扎”的外观，判 Style Copy Risk。

## RULE-10｜Failure Return
当任何 Gate 失败 → 返回最近一个可修正的上游环节 → 因为错误不能靠下游包装掩盖 → Fact 失败回 Input；Route 失败回 Conflict；DNA 失败回 Selection；Strategy 失败回 Causality；Recommendation 失败回 Comparison；Prompt 失败仅重写 Prompt，除非暴露上游事实错误。
