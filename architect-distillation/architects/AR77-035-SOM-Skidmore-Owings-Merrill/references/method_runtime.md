# AR77-035｜METHOD RUNTIME
## Skidmore, Owings & Merrill (SOM)｜Practice Judgement Kernel

## 0｜Authorship Boundary

SOM 是跨代际、跨办公室、跨专业事务所，不是单一建筑师。

因此本 Skill 只蒸馏**跨项目、跨年代反复出现且有证据支持的事务所级判断机制**。
当某机制主要来自具体人物或具体项目时，必须保留作者边界，例如：
- Fazlur R. Khan 的 tube / bundled-tube 结构创新；
- Bruce Graham 与 Khan 在 John Hancock Center 等项目中的合作；
- Gordon Bunshaft 等设计合伙人的具体项目贡献。

不得把这些贡献写成“SOM 一个人的思想”。

## 1｜Evidence Status

### KNOWN

- SOM 官方把建筑、结构工程、城市设计 / 规划等学科的整合描述为事务所长期核心，并强调不同专业并非孤立工作。
- SOM 官方历史把 architecture + engineering integration 视为长期特征，并把 Fazlur Khan 的 tube structural system 作为关键工程贡献之一。
- John Hancock Center 的外筒斜撑体系与混合功能、楼层面积变化和高层结构效率存在直接关系。
- Willis Tower 的 bundled-tube 系统与 Sears 对大、小不同楼层面积的需求共同塑造塔体退台；结构不是事后附加。
- Inland Steel Building 通过办公塔与服务塔分离获得灵活、无内柱的大办公楼层，并体现功能 / 服务 / 结构协同。
- Hajj Terminal 把超大人流、周期性高峰、气候与结构系统作为同一设计问题。
- SOM 城市设计工作持续把建筑、基础设施、公共空间、交通和城市连通性作为系统问题处理；Manhattan West 是近期明确案例。
- SOM 当前研究持续把全生命周期碳、材料效率、结构优化、可再生能源与建筑系统整合为研究方向。
- SOM 长期使用计算分析辅助结构、能源、材料与形态优化；官方历史记录其自 1960s 起开展计算机结构分析与图形研究。

### SUPPORTED INTERPRETATION

AR77 将以上证据转译为以下事务所级方法链：

`项目目标 / 场地 / 运营 /法规 /环境约束`
→ `多专业共同定义性能问题`
→ `建立结构—空间—核心筒/服务—流线—围护—城市关系`
→ `寻找少数高杠杆系统`
→ `用计算 / 模型 /原型 /协调反复验证`
→ `让结构与建筑相互塑造`
→ `以建造、运营、适应性、碳和公共价值校正`
→ `最后才锁定形式`

这不是 SOM 官方发布的固定流程，而是 AR77 对长期反复机制的证据约束抽象。

## 2｜Core Judgements

### J1｜Integration Before Object｜系统整合先于物体
先定义建筑、结构、机电、流线、城市和运营之间的关系，再讨论外形。

### J2｜Structure Can Be Architectural Order｜结构可成为建筑秩序
结构不是自动隐藏，也不是自动“外露”；它应在真实荷载、跨度、刚度、材料效率与空间需求下参与空间和形体组织。

### J3｜Program Shapes System Geometry｜程序塑造系统几何
楼层面积、混合功能、净高、深度、核心筒、物流和灵活性应先于标志性轮廓。

### J4｜Engineering Must Be Measurable｜工程判断必须可验证
风、地震、跨度、材料、能耗、碳、舒适度、流量、施工与成本应通过数据 / 分析验证，不用审美词替代。

### J5｜Public Realm Is Part of the Building System｜公共领域属于系统
城市项目不能只优化单体；地面连通、交通、开放空间、基础设施与街区关系必须一起判断。

### J6｜Efficiency Is Not Minimal Appearance｜效率不是极简外观
效率指结构、材料、面积、能耗、施工、生命周期等综合性能，不等于“少线条 / 玻璃盒”。

### J7｜Research Feeds Practice｜研究必须回到可建造判断
新材料、数字工具、低碳系统或新结构只有能进入项目约束、验证和实施链时才属于本 Runtime。

### J8｜Firm Knowledge Is Collaborative, Not Anonymous
跨专业协作不等于抹去具体作者和责任边界；对历史项目必须保留明确贡献归属。

## 3｜Method Execution

1. 锁定 KNOWN / UNKNOWN / NEED VERIFY。
2. 把 brief 写成 3–5 条系统冲突。
3. 标出必须共同参与判断的专业：Architecture / Structure / MEP / Envelope / Vertical Transport / Urban / Climate / Operations / Cost。
4. 选择 exactly 1 Primary Route；Secondary Route 最多 1。
5. D01 `INTEGRATED_PROBLEM_FRAME` 为基础 DNA；再选 1–3 个必要 DNA，总量 2–4。
6. 为每个 DNA 定义 plan / section / movement / structure / system / performance 的可验证痕迹。
7. 生成三个因果不同策略，而不是三种外观。
8. 用 Comparison + Recommendation Gate 收敛到一个 Dominant。
9. 执行 Contemporary Corrections。
10. Prompt Close 前执行 Prompt Fact Lock。

## 4｜Form Discipline

禁止把以下历史项目机制变成默认形式：
- Lever House 式幕墙板楼；
- John Hancock Center 式 X-bracing；
- Willis Tower 式 bundled-tube / 阶梯轮廓；
- Burj Khalifa 式 Y-plan / spiral setbacks；
- Hajj Terminal 式索膜帐篷；
- One Chase Manhattan Plaza 式塔楼 + 广场构图；
- 任意“corporate modernism”玻璃盒。

只有当当前项目的 KNOWN 条件与 selected Route / DNA / Dominant Strategy 能独立推导相似机制时，才可采用对应系统；仍不得以历史项目为视觉目标。
