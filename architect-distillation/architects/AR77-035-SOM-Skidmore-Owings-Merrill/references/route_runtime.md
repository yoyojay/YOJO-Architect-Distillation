# AR77-035｜PROBLEM ROUTES
## SOM｜Project-Problem Routing

这些是 AR77 从 SOM 长期实践中蒸馏的 **Project-Problem Routes**，不是 SOM 官方固定分类，也不是历史阶段。

---

## R1｜INTEGRATED_TALL_BUILDING_SYSTEM｜高层系统整合

**Trigger**
- 高层 /超高层；
- 风、地震、垂直交通、核心筒、楼层效率、结构或混合功能构成主要约束。

**核心问题**
怎样让结构、核心、楼层、机电、围护与程序彼此协同，而不是先造轮廓。

**Method**
program stack → floorplate needs → core / circulation → structural concept → wind/seismic response → envelope / MEP → constructability / carbon → form.

**主要 DNA**
D01 / D02 / D03 / D04 / D06 / D08

**适用边界**
高层办公、住宅、酒店、混合用途。

**风险**
把 tube / bracing / taper / setback 当成视觉符号；高层必须由结构、风工程、消防、电梯、机电与当地法规专业验证。

**与其他 Route 差异**
它由高度、荷载、核心和垂直系统耦合驱动。

---

## R2｜URBAN_FRAME + PUBLIC_REALM｜城市框架 / 公共领域

**Trigger**
- 多栋建筑、城市更新、交通节点、复杂地块；
- 街区连通与公共空间价值高于单体图标。

**核心问题**
怎样让基础设施、建筑、开放空间、步行与程序共同形成城市系统。

**Method**
movement / transit / infrastructure → public-space network → parcel / massing → ground-floor interfaces → building systems → phasing / operations.

**主要 DNA**
D01 / D05 / D07 / D09

**适用边界**
总体规划、TOD、城市综合体、复杂基础设施上盖、公共空间更新。

**风险**
公共空间被商业私有化；连通性只停留在渲染；分期导致系统断裂。

**与其他 Route 差异**
它以城市尺度连通和公共领域为主因。

---

## R3｜LARGE_SPAN + FLOW INFRASTRUCTURE｜大跨 / 高流量基础设施

**Trigger**
- 机场、交通、展馆、大型公共设施；
- 人流峰值、跨度、轻量化、气候与运营共同主导。

**核心问题**
如何用结构系统和清晰流线支持极端峰值、长跨度与舒适环境。

**Method**
demand peaks → flow zones → span / support logic → climate strategy → services / security → modular construction → future flexibility.

**主要 DNA**
D01 / D02 / D04 / D06 / D07

**适用边界**
机场、车站、会展、大型公共 /文化设施。

**风险**
大跨形式先行、维护困难、声学 /消防 /安防 /客流失效。

**与其他 Route 差异**
它以人流容量 + 结构跨度 + 运营峰值共同驱动。

---

## R4｜ADAPTIVE_EXISTING_SYSTEM｜既有建筑 / 系统再利用

**Trigger**
- 改造、用途转换、既有高层 /办公 /工业系统重用；
- 碳与既有结构价值是重要条件。

**核心问题**
怎样在保留高碳价值的既有结构 /围护 /基础设施同时重新组织用途、日光、通风和运营。

**Method**
existing-asset audit → reuse value → structural / core / envelope limits → new program fit → selective intervention → lifecycle / carbon test.

**主要 DNA**
D01 / D03 / D07 / D09

**适用边界**
办公转住宅、历史 /现代建筑更新、既有结构再利用。

**风险**
为新用途过度拆除；深平面、核心、净高、声学、消防与采光不适配。

**与其他 Route 差异**
它从“已有系统能保留什么”开始，而不是从空白场地开始。

---

## R5｜CLIMATE_CARBON_PERFORMANCE｜气候 / 碳 / 性能系统

**Trigger**
- 全生命周期碳、能源、材料、舒适、韧性是核心 KPI；
- 项目明确要求性能目标而非只做“绿色形象”。

**核心问题**
怎样把减材、结构效率、被动策略、设备系统、材料与生命周期适应性组合成可测量方案。

**Method**
baseline → performance targets → high-impact systems → architecture-engineering co-optimization → simulation / prototype → lifecycle test → design refinement.

**主要 DNA**
D01 / D04 / D06 / D08 / D09

**适用边界**
任何以碳 /能耗 /韧性为明确目标的建筑或城市项目。

**风险**
技术堆叠、绿色装饰、只看运营碳、不看建造与更换周期。

**与其他 Route 差异**
它以量化性能目标作为主因，而不是类型 /形象。

# Route Selection Logic

1. 先写系统冲突，再选 Route。
2. Primary Route exactly 1。
3. Secondary Route = NONE 或最多 1。
4. Secondary 必须解决不同但真实的次级冲突。
5. R1 不因为“塔楼”就自动启用；高度、核心、风 /地震 /结构耦合必须真实重要。
6. R2 只有公共领域 /城市连通真实决定项目时启用。
7. R3 只有跨度 /高流量 /峰值运营真实重要时启用。
8. R4 只有既有资产重用真实存在时启用。
9. R5 需要明确 performance KPI；没有基线 /指标时先列 NEED VERIFY。
10. 未选 Route 禁止回流 Recommendation / Prompt / Handoff。
