# AR77-018｜Problem Routes

## R1｜URBAN_LIVING_LOOSENING｜城市生活松绑
**Trigger**：高密度居住、小型复合生活、传统房间定义过强、需要不同独处/共享关系。  
**核心问题**：如何让住宅不被单一家庭模型和封闭体量锁死。  
**Method**：M1 + M2 + M3 + M4。  
**主要 DNA**：D1、D2、D3、D4、D6。  
**边界**：隐私、安防、声学、消防、气候控制必须先过线。  
**风险**：把“开放”浪漫化，牺牲真实居住舒适度。  
**区别**：重点是生活关系与空间解释权，不是公共机构或景观沉浸。

## R2｜DISTRIBUTED_PUBLIC_ART｜分布式公共/艺术场
**Trigger**：美术馆、文化设施、社区公共项目，希望建筑活动与街道/户外互相渗透。  
**核心问题**：如何让不同内容拥有独立空间，同时让城市与公共活动穿行其间。  
**Method**：M1 + M2 + M4。  
**主要 DNA**：D1、D2、D4、D5、D7。  
**边界**：展陈控制、票务、安全、后勤、消防分区不可被“开放”消解。  
**风险**：碎片化导致寻路和运营低效。  
**区别**：以城市公共关系为主，不以住宅亲密度或自然沉浸为主。

## R3｜ENVIRONMENT_AS_ROOM｜环境即房间
**Trigger**：自然场地、艺术与自然共构、季节/风/声/光是项目核心媒介。  
**核心问题**：建筑如何让环境进入体验，而不是把自然框在窗外。  
**Method**：M1 + M4 + M5。  
**主要 DNA**：D4、D5、D7、D8。  
**边界**：热湿、雨雪、耐久、维护、虫害、声学与作品保护必须验证。  
**风险**：把某个著名壳体或大开口误当通用答案。  
**区别**：环境参与是主因，几何只是后果。

## R4｜PROGRAM_AS_LANDSCAPE｜程序成为可游走关系场
**Trigger**：学习、文化、公共复合项目中，功能需要相互看见、相互接近但不必被走廊严格分隔。  
**核心问题**：如何用路径、距离、地形/高差或空间连续性组织多种活动。  
**Method**：M1 + M3 + M4 + M5。  
**主要 DNA**：D3、D4、D5、D6、D8。  
**边界**：无障碍、疏散、声学、清晰寻路与运营分区必须成立。  
**风险**：把“连续”误读成无边界、无功能差异。  
**区别**：重点是程序与移动的连续关系，不预设分散体量。

## Route Selection
1. 先识别主冲突，只选 1 个 Primary Route。
2. 若第二 Route 解决的是不同且真实存在的次冲突，可标 Secondary Route；不得超过 1 个。
3. Secondary Route 只能贡献一个明确机制，不能把两条 Route 全量叠加。
4. 若项目事实不足以选 Route，标 NEED VERIFY 并只问 1–3 个关键问题。
