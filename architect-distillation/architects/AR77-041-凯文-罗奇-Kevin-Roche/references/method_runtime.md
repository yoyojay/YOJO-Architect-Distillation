# AR77-041 | Kevin Roche — Method Runtime

此模块是可调用的项目判断操作，而非罗奇本人写过的公式。方括号 E 编码指向研究时核实的机构资料；客户运行时可引用链接核对，但不可把蒸馏推论伪装成原话。

## Evidence-anchored method kernel
**NEED → PEOPLE / INSTITUTION → ENVIRONMENTAL RELATION → SPATIAL SYSTEM → TECHNICAL & CIVIC PROOF → REVISE.**

- **从真实需要开始**：罗奇在普利兹克资料中以 General Foods 项目说明，设计由需要、办公人员及合适的环境开始，而不受风格分类决定。[E1 KNOWN]
- **人的生活与共同体优先于纯几何**：访谈中强调人与社区在建筑中的重要性，并将建筑视为艺术与社会服务。[E2 KNOWN]
- **建筑不孤立**：Yale University Press 研究归纳罗奇把交通、基础设施、景观及公共空间纳入建筑问题；这是二手学术解释，不是逐字本人理论。[E8 SUPPORTED INTERPRETATION]
- **将组织转换为空间关系**：福特基金会办公与共享庭院的关系、奥克兰博物馆的展馆—城市公园整合、美术馆长期增建的整体计划，证明不同项目可用不同机制。[E4/E5/E7 KNOWN]
- **反复提问后形成形式**：罗奇明确提及从沙里宁学到深入研究与反复提问、并非先锁定形式；他区分其与某些先有形态的个例。[E2 KNOWN]
- **建筑形式必须有建成能力**：其与 John Dinkeloo 合作分工中，Roche 主要主导设计、Dinkeloo 关注建造；不要把结构构件或材料当成 Roche 的永久默认。[E2/E3 KNOWN]

## Runtime causal sequence
1. **Need statement**：把委托改写成一项可验证的使用者/组织难题；若客户只给形式偏好，先请求真实运营目标。
2. **People + power map**：绘出公共访问、员工/专业人员、维护后勤、私密/安保的权利与时段矩阵，明确冲突。
3. **Context map**：确认项目对道路、城市步行、室外公共地面、景观、既有建筑与未来改造的责任。
4. **Select one problem Route**：由现有主要矛盾驱动；允许记录次要适配，但不得未解释地叠加两个主体 Route。
5. **Select a limited DNA set**：只选对当前主要冲突有因果贡献的 DNA；并把未选项登记为不得回流。
6. **Draw mechanism**：逐一输出总平关系、平面分区、剖面公共—专业关系、出入路径、环境/结构系统验证草图；无事实不写定具体材料、屋顶或形状。
7. **Make A/B/C causally distinct**：改变共享空间的生成位置、访问制度或场地/机构组织原则，而不是替换造型材质。
8. **Operate + correct**：验证气候、声学、私密/安保、包容性、疏散、可维护性及财政适用。
9. **Recommend**：只认一个独立可成立 Dominant，可选从另一个策略借用一个有限子机制。
10. **Fact-Locked prompt**：只把已确认项目事实和所选机制翻译成能看清空间关系的图像描述。

## When the method does NOT fit
- 用户只要求复刻某知名罗奇作品形式；先转为功能机制问题。
- 项目目标排斥任何对外部关系、使用者体验、运维进行验证的空间判断；标 PARTIAL/NOT FIT。
- 对无法验证公共开放权、运维与真实使用者的“巨型中庭 / 屋顶公园”提案，必须降级为候选假设。
- 室内私人功能、高安保项目不因罗奇有公共作品而强制引入完全公共的通廊。

## Evidence status reminder
`KNOWN` = 文献明确记载的建筑事实/本人语句；`SUPPORTED INTERPRETATION` = 从多个项目推导的可审查机制；
`NEED VERIFY` = 项目条件不足的待验证事实；`UNKNOWN` = 无证据，不得出现在具体设计锁。
