# AR77-048｜DESIGN DNA RUNTIME
## Christian de Portzamparc｜判断机制不是形式菜单

下列 9 项 DNA 是 AR77 根据特定证据建立的 **transferable mechanism abstraction**，不是 Christian de Portzamparc 亲自发表的九条固定原则。

**选择契约**：D01 必选；另选 2–3 个有 KNOWN Trigger 的 DNA，合计 3–4。未选 DNA 在本轮完全禁用，不得进入 A/B/C、Recommendation、Keep、Next、Prompt 或 Visual Handoff。

## D01｜CITY_AS_COLLECTIVE_INTERIOR｜城市作为可居住的集体内外空间
**判断含义**：建筑不仅提供对象，还通过内外场所、街道和邻里关系组成可使用的城市。
**Trigger**：完整项目分析的基础判定，无论单体或多建筑。
**Spatial Operation**：site map 记录 buildings / voids / entries / everyday users / neighbors / street paths / activities；先找关系统领问题。
**适用边界**：全部项目；对孤立地块只检验其真实城市邻接，不能虚构都市街区。
**Failure Mode**：只谈“城市性”，效果图里只有孤立地标和无人的街道。
**可验证空间痕迹**：site + ground plan 明确至少一组真实的建筑—城市—人的关系与权属。
**证据追溯**：1994 Pritzker speech / bio。

## D02｜VOID_AS_POSITIVE_SPACE｜空隙作为积极的城市空间
**判断含义**：建筑之间的 void 可与建筑本身同等重要，需有明确功能、边界和使用权。
**Trigger**：多个体量或建成边界间存在可识别的空隙、通行 / 停留 / 生态或日照问题。
**Spatial Operation**：void inventory → ownership/public-access matrix → edge / path / pause / daylight / servicing → usage and maintenance tests。
**适用边界**：街区、集合住宅、校园、文化园区。
**Failure Mode**：随机留白；以后围栏化；空隙阴暗、无障碍不足或成风廊。
**可验证空间痕迹**：site void diagram + ground access + daylight / use rights。
**证据追溯**：Portzamparc 1994 biography + Hautes Formes。

## D03｜FLEXIBLE_OPEN_BLOCK_RULES｜可变的开放街区规则
**判断含义**：允许建筑相异并非任意错动，而是利用边界、高度、间距、日照、街道与管理规则保障多样性。
**Trigger**：真实多地块、多建筑师或渐进式街区开发需要规则治理。
**Spatial Operation**：define allowed envelope and spacing + sunlight/access thresholds + public/private rights + phase governance → test multiple design scenarios。
**适用边界**：城市规划、多主体住宅街区；不用于任意单栋。
**Failure Mode**：把 Masséna 外观当模板；放任不具备性能的自由形体；规则与产权不匹配。
**可验证空间痕迹**：可执行的 code / block plan / variation scenarios / access agreement。
**证据追溯**：2Portzamparc Quartier Masséna。

## D04｜DIFFERENCE_WITH_URBAN_COHERENCE｜差异中保持街道整体
**判断含义**：不同尺度、用途和建筑身份可共存，街道及集体空间提供整体秩序。
**Trigger**：不同方案、功能或建造阶段需要共处而不形成混乱。
**Spatial Operation**：shared street edges / wayfinding / open-space hierarchy → independent building rules → permeability / legibility tests。
**适用边界**：多建筑群、校园、混合社区。
**Failure Mode**：每栋标新立异导致街道方向、舒适与可读性消失。
**可验证空间痕迹**：urban section + street-view hierarchy + coherent shared access。
**证据追溯**：Masséna 概念与项目运行说明。

## D05｜EVERYDAY_PUBLIC_GROUND｜公共地面上的真实生活
**判断含义**：居民和使用者应能接近、使用、停留；公共承诺必须有管理 / 安全现实。
**Trigger**：场地地面层影响邻里活动、开放街道、社区或多功能机构可达。
**Spatial Operation**：user times / pedestrian desire lines / shared-private thresholds / active edges / security schedule / manager responsibilities。
**适用边界**：公共设施、住宅更新、街区、文化校园。
**Failure Mode**：效果图里的“开放”其实门禁封闭、私有化或物业不愿维护。
**可验证空间痕迹**：day/night access map + user program + legal public access plan。
**证据追溯**：Hautes Formes 的公共穿行意图及后来围栏的现实校正。

## D06｜DAYLIGHT_BETWEEN_VOLUMES｜体量间的可验证日光
**判断含义**：高低错配、间距和多朝向开口只有改善真实采光与生活体验才成立。
**Trigger**：建筑间遮挡、双面 / 多向采光、庭园与私密性真实需要权衡。
**Spatial Operation**：solar / shadow / view / privacy map → feasible height and separation → seasonal comfort and glazing test。
**适用边界**：集合住宅、街区和多体量建筑。
**Failure Mode**：机械错动体量；在寒冷/炎热气候造成热负荷和光污染。
**可验证空间痕迹**：actual solar section and sky-view / glare study。
**证据追溯**：Masséna all-side daylight 说明，Hautes Formes 不同高度与视线。

## D07｜AUTONOMOUS_PROGRAM_PARTS｜自治功能单元共同工作
**判断含义**：每一学科 / 演出 / 展示有独立环境要求，但可经由适当中介组成一座“内部街区”。
**Trigger**：教育、演出、文化综合等含多种需要声学、运营与安全自治的功能。
**Spatial Operation**：program autonomy + privacy / noise matrix → shared nodes and interfaces → backstage/public separation。
**适用边界**：文化、教育、复合机构。
**Failure Mode**：把所有功能暴露在共享空间、靠异形体块假装“多样”。
**可验证空间痕迹**：functional bubble + acoustic/security zoning + plan/section adjacency。
**证据追溯**：Cité de la Musique 西翼与东翼。

## D08｜CIRCULATION_AS_INTERNAL_URBAN_STREET｜路径作为内部城市街道
**判断含义**：水平/竖向公共路线可产生遇见与场所感，但必须服务真实端点、容量和导向。
**Trigger**：多使用者、复杂楼层或公众路线存在分流 / 交流 / 到达问题。
**Spatial Operation**：origin/destination/peak flow → vertical and horizontal shared route → pauses/views → accessible alternative and service separation。
**适用边界**：文化、教育、音乐、公共综合体。
**Failure Mode**：螺旋廊或长走道形式化；拥堵、无障碍劣化、后勤交叉。
**可验证空间痕迹**：network circulation + section + wayfinding / crowd and egress test。
**证据追溯**：Cité de la Musique。

## D09｜THRESHOLD_FILTER_FOR_PUBLIC_EVENT｜公共事件的阈值过滤
**判断含义**：城市到艺术活动的过渡可通过光、声、视线与 foyer 逐层建立，同时保持必要隔离。
**Trigger**：真实 performance/visitor experience 需在外界与受控室内环境间过渡。
**Spatial Operation**：audience timeline → exterior boundary / foyer / controlled hall layers → selective views / shade → acoustic/fire/MEP / operation review。
**适用边界**：音乐厅、表演、展览、文化建筑。
**Failure Mode**：复制数百根细柱、特定光过滤幕墙或某个剧院阳台体系；忽略声学性能。
**可验证空间痕迹**：audience time-sequence + acoustic/privacy/light and egress overlay。
**证据追溯**：Philharmonie Luxembourg 官方事务所项目与声学顾问名单。

## DNA SELECTOR｜实际执行而非展示目录

1. D01 强制；D02–D09 中再选 2–3 条最必要、有 KNOWN 支持的 DNA，总计 3–4。若实际 Trigger 不够，问最多 3 个关键问题，不虚凑。
2. D02 必须有真实 void 的交通、光照或使用问题；空隙不等于总需要开辟通道。
3. D03 必须是多地块 / 多团队可治理的街区规则情境；单栋不调用。
4. D04 必须有多种差异主体需要形成 urban coherence；不得为了形式多样而乱拼。
5. D05 必须核查 public access、物业、运营与用户活动；未验证的活动记 NEED VERIFY。
6. D06 必须有 verified orientation 或建立日照/眩光测试计划；不能由建筑师名字推定体量。
7. D07 需要真实自治 / 共享功能；不得凭“文化性”加多个不必要功能。
8. D08 需要已知主要人群、端点、流量；不得复制螺旋廊。
9. D09 需要真实 event/auditorium threshold、声学与运营问题；其他建筑不能凭空选。
