# AR77-032 Bernard Tschumi｜Design DNA Runtime

> 以下 DNA 是 AR77 对已验证方法机制的运行化蒸馏，不是 Bernard Tschumi 本人公布的“DNA 清单”。不设固定选择数量：只选当前 Route 与项目冲突真正需要的最小集合。

## DNA-01｜SPACE–MOVEMENT–EVENT 三域分离 / 重组
**判断含义**：空间、身体移动与事件不必一开始合并为一个静态功能图。  
**Trigger**：项目活动随时间变化，或“房间表”无法解释真实使用。  
**Spatial Operation**：分别绘制空间、movement、event，再决定 alignment / superposition / disjunction。  
**适用边界**：需要真实事件逻辑；不用于无意义的复杂化。  
**Failure Mode**：图解很复杂，但平面与剖面没有任何变化。  
**可验证空间痕迹**：路径、节点、占用时序或空间转换能与事件一一对应。

## DNA-02｜NOTATION OF ACTION｜行动记谱
**判断含义**：用序列、轨迹、时间或情境补足传统图纸看不见的行动。  
**Trigger**：movement / event / temporal change 对设计结果关键。  
**Spatial Operation**：sequence frames、movement trace、time strip、occupancy scenario。  
**适用边界**：notation 必须用于决策，不是表现风格。  
**Failure Mode**：漂亮图示与建筑无因果关系。  
**可验证空间痕迹**：notation 中的关键变化能在 plan / section / threshold / operation 中找到对应。

## DNA-03｜PROGRAM JUXTAPOSITION / SUPERPOSITION｜程序并置 / 叠置
**判断含义**：程序可以独立发展后再以有意关系组合，不必追求先验和谐。  
**Trigger**：复合 program 存在共享、交叉、分时或潜在冲突。  
**Spatial Operation**：水平、垂直或时间叠置；明确 shared / separated / buffered zones。  
**适用边界**：必须验证声学、安保、后勤、消防、独立运营。  
**Failure Mode**：为了“刺激”而制造无效冲突。  
**可验证空间痕迹**：邻接、层叠、共享空间与分界在平剖中清楚可读。

## DNA-04｜PRODUCTIVE DISJUNCTION｜有目的的不一致
**判断含义**：space / movement / event 不一定完全同步；差异可成为设计发动机。  
**Trigger**：过度整齐的功能逻辑压平了真实行为，或某种错位能产生新的使用可能。  
**Spatial Operation**：局部错位、延迟、交叉、可控冲突或多重读取。  
**适用边界**：不得损害 safety / accessibility / operation。  
**Failure Mode**：把“不协调”当审美目标。  
**可验证空间痕迹**：错位产生明确的使用选择、停留、视线或事件，而不是任意碎裂。

## DNA-05｜VECTOR｜移动向量
**判断含义**：路径不是剩余交通，而是组织 program 与事件的主动系统。  
**Trigger**：到达、穿越、转换、展览序列或跨层连接决定体验。  
**Spatial Operation**：建立 primary / secondary vectors、交叉点、停留节点与返回逻辑。  
**适用边界**：必须满足无障碍、疏散、辨向和日常效率。  
**Failure Mode**：路径成为夸张斜线或雕塑。  
**可验证空间痕迹**：movement hierarchy 在 plan / section / sequence 中一致可读。

## DNA-06｜ENVELOPE AS SHELTER + CHANNEL｜包络作为庇护与导流
**判断含义**：envelope 不只是立面构图，它同时界定环境并与 movement 发生关系。  
**Trigger**：外壳、路径、气候或大空间边界必须共同解决。  
**Spatial Operation**：以 shelter、entry、movement、light / climate boundary 组织 envelope。  
**适用边界**：材料、结构、开口、几何不得凭风格自动指定。  
**Failure Mode**：把动态外形误当 movement logic。  
**可验证空间痕迹**：包络的开合、厚度、入口或环境响应可追溯到真实条件。

## DNA-07｜ACTIVE IN-BETWEEN｜主动的“之间”
**判断含义**：既有 / 新建、两个 program、两层边界之间的剩余空间可成为事件载体。  
**Trigger**：更新、复合 program 或双重系统之间存在可被激活的间隙。  
**Spatial Operation**：把 in-between 明确成 circulation / gathering / production / display / transition 等真实用途。  
**适用边界**：不能把所有缝隙都浪漫化；消防、维护、气候与管理必须成立。  
**Failure Mode**：制造无法使用、维护的剩余空间。  
**可验证空间痕迹**：in-between 有尺寸、可达性、时间表与具体使用。

## DNA-08｜CONCEPT–CONTEXT–CONTENT RELATION｜概念—语境—内容关系
**判断含义**：三者关系必须被主动选择，而不是默认“融合”。  
**Trigger**：场地 / 历史 / program 与设计概念之间存在强张力。  
**Spatial Operation**：明确 reciprocity / conflict / strategic independence，并落到 siting、orientation、section、access、threshold。  
**适用边界**：heritage / ecology / climate / regulation 是硬边界。  
**Failure Mode**：把 conflict 当任意对抗，或把 reciprocity 当复制环境外观。  
**可验证空间痕迹**：关系可在总平、剖面、到达与功能分布中被说明。

## DNA-09｜CONCEPT-FORM｜概念—形式双向强化
**判断含义**：form 必须是 concept 的可验证物化；同时 form 的反馈可以修正 concept。  
**Trigger**：多维复杂条件需要一个可持续组织装置。  
**Spatial Operation**：将 concept 写成一条可检验命题，再列出其 plan / section / movement / operational consequences。  
**适用边界**：概念不能凌驾于性能与法规。  
**Failure Mode**：先有造型，再写概念说明。  
**可验证空间痕迹**：去掉渲染与材料后，组织命题仍能从图纸读出。

# DNA Selection Logic

不使用固定数量配额。

1. Primary Route 必须至少有一个 Primary DNA。
2. 只有当某个 DNA 解决一个**不同且已验证的项目冲突**时才加入。
3. 每个 Selected DNA 必须写：
   `Trigger → Spatial Operation → Plan/Section/Path trace → Risk → Test`
4. 若两个 DNA 做同一件事，保留因果更清楚的一个。
5. 若 DNA 只带来视觉特征，不改变 plan / section / movement / operation，删除。
6. 未选 DNA 不得在 Strategy、Recommendation、Prompt 或 Handoff 回流。
7. 如后续发现必须使用未选 DNA，先显式修改 Selected DNA，再重跑受影响的策略。
