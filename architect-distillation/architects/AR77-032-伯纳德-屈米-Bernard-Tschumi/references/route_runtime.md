# AR77-032 Bernard Tschumi｜Problem Routes

> Route 来自 Bernard Tschumi 官方回顾展反复归纳的五个方法主题。它们在 Runtime 中被转译成项目问题路由，不是历史时期，也不是形式分类。

## R1｜SPACE_EVENT｜空间 × 事件

**Trigger**  
项目真正的难点是活动、时间、身体行动或使用方式，而不是房间面积本身。

**核心问题**  
空间如何承接、强化或允许事件改变其意义？

**Method**  
分别记录 Space / Movement / Event；用 sequence 或 scenario 检查三者的对齐、错位与变化，再决定空间组织。

**主要 DNA**  
DNA-01 / DNA-02 / DNA-04

**适用边界**  
文化、教育、公共、展演、混合使用等事件密度较高的项目尤其适合；纯静态、高度标准化流程项目需谨慎。

**风险**  
把“事件”变成戏剧化噱头；忽略日常运营、疏散、噪声、可达性。

**与其他 Route 的差异**  
R1 从发生的行为出发；不是从功能叠置、流线外壳、场地关系或形式统一性出发。

---

## R2｜PROGRAM_SUPERPOSITION｜程序 × 叠置

**Trigger**  
多种功能相互依赖、争夺空间或希望产生新的邻接 / 时间共享。

**核心问题**  
哪些 program 应分开，哪些应 juxtapose / superpose，哪些冲突能产生价值？

**Method**  
先拆分 program layer，再测试水平 / 垂直 / 时间叠置；把 useful collision 与 harmful conflict 分开。

**主要 DNA**  
DNA-03 / DNA-04 / DNA-07

**适用边界**  
复合文化、校园、更新、公共综合体、多时段共享项目。

**风险**  
为了“冲突”而冲突；声学、安防、物流、隐私、消防与独立运营失控。

**与其他 Route 的差异**  
R2 以 program relation 为主因，不把 movement 或 context 自动置于第一位。

---

## R3｜VECTOR_ENVELOPE｜向量 × 包络

**Trigger**  
项目由移动、到达、转换、基础设施、连续路径或大量流线关系主导，同时需要明确建筑边界。

**核心问题**  
movement vector 如何组织空间，而 envelope 如何同时提供 shelter、环境边界与路径导向？

**Method**  
先建立主要 / 次要 vector 与停留节点，再让 envelope 响应经过验证的气候、结构、运营和 movement relation。

**主要 DNA**  
DNA-05 / DNA-06 / DNA-02

**适用边界**  
交通、校园连接、展览序列、公共流线复杂项目。

**风险**  
路径成为形式姿态；envelope 被降格为动态图形；无障碍、疏散和辨向被牺牲。

**与其他 Route 的差异**  
R3 的因果起点是 movement + enclosure，而不是 program collision 或 context relation。

---

## R4｜CONTEXT_CONTENT｜语境 × 内容

**Trigger**  
考古、历史、城市网格、地景、文化或既有建筑对项目具有强约束，而新 program 又要求新的组织。

**核心问题**  
Concept、Context、Content 应当互相呼应、保持张力，还是局部独立？

**Method**  
明确三者关系并给出理由；通过 site plan、section、approach、heritage / climate / operation test 验证，而不是以“融入环境”或“故意对抗”作为口号。

**主要 DNA**  
DNA-08 / DNA-07 / DNA-09

**适用边界**  
遗产 / 考古、城市更新、既有建筑增补、强场地公共项目。

**风险**  
把 conflict 误成任意对抗；把 reciprocity 误成形式模仿；忽略法定保护与生态边界。

**与其他 Route 的差异**  
R4 首先处理项目与外部条件的策略关系。

---

## R5｜CONCEPT_FORM｜概念 × 形式组织

**Trigger**  
项目复杂度高、条件多，缺乏一个能让 program、technology、social relation 与 spatial order 共同工作的组织命题。

**核心问题**  
什么概念可以成为可验证的 organizing device，并在形式与概念之间形成双向强化？

**Method**  
提出一个清楚 concept；列出它必须产生的 plan / section / path / operational consequences；只保留能被这些后果验证的 form。

**主要 DNA**  
DNA-09 / DNA-03 / DNA-05

**适用边界**  
复杂公共建筑、科研教育、城市综合体、需要长期演化的项目。

**风险**  
concept 退化成口号；form 先出现再倒推理由；单一概念压制性能与使用差异。

**与其他 Route 的差异**  
R5 以 coherence / organizing device 为主因，而不是某一特定事件、程序冲突、路径或场地矛盾。

---

# Route Selection Logic

1. 先从用户的 **dominant project conflict** 选择一个 Primary Route。
2. 只有当第二个冲突不能被 Primary Route 解释时，才允许一个 Secondary Route。
3. Secondary Route 只提供一个有限机制，不建立第二套平行概念。
4. Route 选择必须写出：`Trigger → why this route → what it changes in plan/section/path`。
5. 未选 Route 不得在 A/B/C、Recommendation 或 Prompt 中偷偷回流。
6. 若所有 Route 都只产生造型而不改变真实项目关系，判定 Route 选择失败，退回 Core Problems。
