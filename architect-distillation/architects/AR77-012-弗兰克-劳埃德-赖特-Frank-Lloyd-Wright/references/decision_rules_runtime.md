# AR77-012｜DECISION RULES

1. **Fact Lock**  
当关键事实未知 → 保持 UNKNOWN / NEED VERIFY → 因为具体化会污染后续判断 → 通过输入追溯验证 → 若不可验证则泛化或删除。

2. **Fit**  
当项目问题确实需要地点、生活、连续空间与整体协调 → 才使用本 Kernel → 因为 Fit 来自问题而非形象 → 通过冲突定义验证 → 若只能靠“像赖特”成立则 NOT FIT。

3. **Route**  
当一个冲突主导项目 → 选择一个 Primary Route → 因为路由必须保持因果清晰 → 通过 Core Question 验证 → 若两条同等主导则重新定义冲突。

4. **DNA**  
当 Route 已选 → 只选解决冲突所需 3–5 DNA → 因为未选机制会造成回流 → 通过 plan/section/path trace 验证 → 无痕迹 DNA 删除。

5. **Strategy**  
当生成 A/B/C → 每套必须有不同 Core Cause → 因为策略差异必须是因果差异 → 通过至少两项 plan/section/movement 改变验证 → 只换材料/造型/程度则 FAIL。

6. **Plan–Section–Movement**  
当提出空间机制 → 必须说明平面、剖面、路径中至少两项如何改变 → 因为判断必须落到空间 → 通过图纸测试 → 若只有立面语言则返回 Route/DNA。

7. **Performance**  
当提出开放、连续、结构、遮蔽或室内外关系 → 同步验证 climate/access/fire/structure/MEP/acoustics/privacy/operations → 因为历史机制不能豁免当代性能 → 若失败则改实现手段。

8. **Recommendation**  
当比较完成 → 选择 one Dominant + at most one bounded Borrowed Mechanism → 因为推荐必须可独立成立 → 通过删除其他策略后仍完整验证 → 若必须三套混合则重新比较。

9. **Critic**  
当审查现有方案 → 先查 Method/Route/DNA/几何因果 → 再查视觉效果 → 因为强图像可能掩盖未解决建筑问题 → 若因果不成立则返回 conflict。

10. **Failure Return**  
当空间痕迹或性能测试失败 → 返回 conflict/Route/DNA → 因为失败应修正判断链 → 禁止转向 façade styling 补救。
