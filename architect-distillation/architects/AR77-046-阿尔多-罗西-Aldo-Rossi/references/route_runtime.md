# AR77-046｜PROBLEM ROUTES
## Aldo Rossi｜Evidence-Bounded Project-Problem Routing

**身份**：下列五条是 AR77 以 Rossi 文献与项目证据建立的项目问题路由，不是 Rossi 官方的“五种时期 / 风格”。Router 的输入必须是项目冲突而不是某件代表作的造型。

## R1｜URBAN_FABRIC_RECOMPOSITION｜既有城市结构 / 连续与重组

**Trigger**
- 现有街区、建筑片段、街道、场所或公共生活被更新 / 拆迁 / 功能变化割裂；
- 新建 / 改建会改变城市界面或历史联系。

**核心问题**
哪些已形成城市身份的空间关系需要延续，哪些必须为当代 program 改造，才能把新介入作为城市的一部分而不是孤立物体？

**Method**
`verified urban artifacts → existing paths / edges / activity → permanence value → preserve/change boundary → new city-interface / program → staged operational validation`

**主要 DNA**：D01 / D03 / D04 / D06；按实际冲突只选其中 2–4 项。  
**适用边界**：历史城区更新、机构扩建、城市修复、重要公共节点。  
**风险**：虚构历史、伪古董、强行统一老城、遗产 / 产权 / 街区治理冲突。  
**与其他 Route 差异**：由既有 *urban fabric* 的破裂与延续驱动，不是纯类型实验或一个纪念对象。

**Hard Stop**：没有现场、产权、保护与历史依据时只能给暂定诊断和 NEED VERIFY。

## R2｜TYPE_WITH_PROGRAM_EVOLUTION｜类型秩序 / 用途演化

**Trigger**
- 现有或潜在的建筑类型关系（院落—街道、走廊—房间、公共空间—服务）需要适应新 program；
- 业主希望长期使用弹性而不是短期表皮更换。

**核心问题**
怎样辨认地方类型的结构性关系，再让其随当代使用变化，而不直接复制历史平面 / 形式？

**Method**
`local type evidence → spatial invariant hypothesis → current-user program / safety → variation / adaptation → plan-section / operation / future-change tests`

**主要 DNA**：D01 / D02 / D04 / D08。  
**适用边界**：住宅、学校、文化 / 机构设施、类型转译、再利用。  
**风险**：把特定模板普遍化；类型压过真实家庭、消防、光、通风或当代运营。  
**与其他 Route 差异**：由 **空间类型与新 program** 的矛盾驱动，不以 monument 或视觉类比作为依据。

**Hard Stop**：找不到可证地方类型时不准凭 Rossi 的代表作替代；改从使用关系分析。

## R3｜COLLECTIVE_MEMORY_CIVIC_LOCUS｜集体记忆 / 公共场所

**Trigger**
- 真实历史事件、共同体记忆、已有纪念 / 公共设施与场所身份是设计任务的重要组成；
- 城市需要处理 remembrance 与持续日常生活之间的关系。

**核心问题**
如何让集体记忆成为可到达、可共同使用、可在时间中演化的公共空间关系，而非一个纪念性的几何形象？

**Method**
`whose memory? + evidence → locus / existing trace → access + public rite / everyday use → spatial threshold / route / collective ground → inclusive memory / operations / conservation test`

**主要 DNA**：D01 / D03 / D04 / D05 / D06。  
**适用边界**：墓园、纪念、公民文化、历史公共空间、灾后修复。  
**风险**：单一叙述抹去多元记忆；用“城市死寂感”作效果图；回避无障碍、宗教、照护和日常运营。  
**与其他 Route 差异**：由具有来源的 **collective memory** 驱动；不得仅因项目“需要有气质”而启用。

**Hard Stop**：无社区或档案证据则不得宣称“集体记忆”；改为 NEED VERIFY 和参与式研究。

## R4｜HOUSING_AS_URBAN_COMMUNITY｜居住作为城市 / 日常集体秩序

**Trigger**
- 住宅或混合用途项目存在重复户型 / 高密与公共交往、城市街道的矛盾；
- 建筑要成为邻里日常结构的一部分。

**核心问题**
如何让重复的住宅逻辑在密度、舒适度与预算中成立，并通过公共路径 / 可访问地面 / 社区服务支持生活？

**Method**
`residents / everyday patterns → city interfaces → type and repeatable access → private-shared-public gradient → phase / maintenance / safety / social-service test`

**主要 DNA**：D01 / D02 / D06 / D08。  
**适用边界**：保障 / 公共 / 机构住房、居住集群、混合社区。  
**风险**：一条长廊变成表演性符号；巨尺度单调；社区服务不足；安防、管理、密度和社会支持失效。  
**与其他 Route 差异**：由普通居住日常与 **building city** 的联合责任驱动，不能仅以“有拱廊”判定成功。

**协作边界**：Gallaratese / Monte Amiata 需承认 Carlo Aymonino 负责总体项目 / 邀请 Rossi 参与。

## R5｜TEMPORARY_THEATRE_PUBLIC_EVENT｜临时事件 / 建筑—城市的舞台

**Trigger**
- 真实临时剧场、节庆、市集、文化活动或限期公共项目需要回应特定城市 / 场地；
- 临时性、可拆装、聚集与城市展示具有现实价值。

**核心问题**
如何使建筑 / 活动与城市视线、路径、公共集聚和时间安排发生关系，而非复制 Teatro del Mondo 的水上塔楼？

**Method**
`event program + audience → locus / urban ritual → public approach / staging → temporary vs permanent infrastructure → safety / climate / logistics / removal test`

**主要 DNA**：D01 / D03 / D07 / D09。  
**适用边界**：临时文化、公共活动、展览、节庆、剧场性设施。  
**风险**：建筑景观化、临时结构消防 / 稳定 / 疏散不足、一次性浪费、过度主题化、误读为浮动形体。  
**与其他 Route 差异**：由真实 **time-limited event + city relationship** 驱动。

**Hard Stop**：水上 / 木构 / 灯塔 / 锥顶皆不默认；没有活动事实时不选本 Route。

## Route Selection Algorithm

1. 先从 KNOWN facts 写出主冲突，不先从作品和图像选择 Route。
2. Primary Route **exactly 1**。如存在真实不同次级冲突，可选 Secondary Route **max 1**，否则 `NONE`。
3. Route 不是建筑类型列表：项目即使是学校，也可能因记忆问题走 R3、类型问题走 R2、城市断裂走 R1。
4. 为 Primary 写 `Trigger / Problem / Method / Fit Boundary / Risk / Difference / Evidence Label`。
5. Secondary 不得取代 Primary，也不能把另一个方案的全部 DNA 偷渡进入。
6. 未选 Route 不得进入 A/B/C 的正向来源、Dominant、Keep、Next、Prompt 或 Handoff。
7. 若事实不支持任何 Route：`NOT FIT / NEED VERIFY`，不假造 Rossi 方法；用户资料不足每轮只问 1–3 个关键问题。
8. 城市类 Route 需验证场地、社区、遗产、运营和治理；不凭单张视觉图完成路由。
