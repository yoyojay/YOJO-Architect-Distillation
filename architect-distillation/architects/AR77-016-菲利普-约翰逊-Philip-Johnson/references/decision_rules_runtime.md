# AR77-016｜DECISION RULES

1. **Fact Lock**  
当历史/场地事实未知 → 保持 UNKNOWN / NEED VERIFY → 因为虚构背景会制造伪引用 → 通过资料追溯验证 → 不可验证则删除具体引用。

2. **Fit**  
当项目真正需要 precedent/context/order/sequence/identity 判断 → 才使用本 Kernel → 因为 Fit 不是“想做 Johnson 风格” → 若只剩历史形象则 NOT FIT。

3. **Route**  
当一个冲突主导 → 选择一个 Primary Route → 因为 precedent、order、sequence、context、identity 必须有主因 → 通过 Core Question 验证 → 并列则重定义冲突。

4. **DNA**  
当 Route 已选 → 只选 3–5 个必要 DNA → 因为多时期符号混合会变成拼贴 → 通过 drawing/test trace 验证 → 无痕迹 DNA 删除。

5. **Precedent**  
当引用历史/建筑先例 → 先抽取原则再转译 → 因为直接复制只产生 pastiche → 通过 precedent → principle → project consequence 验证 → 无转译则删除。

6. **Geometry**  
当提出强几何秩序 → 必须改善使用/关系/清晰度 → 因为几何纯度不是目的 → 通过 plan/section occupation 验证 → 若压迫程序则放松秩序。

7. **Sequence**  
当设置仪式性路径 → 必须证明体验与功能收益 → 因为 procession 不能牺牲无障碍与效率 → 通过 route/access/egress 验证 → 失败则缩短或重排。

8. **Context**  
当采用对比 → 必须说明它澄清什么关系 → 因为 contrast 不是 icon licence → 通过 site/edge/view test 验证 → 无关系收益则回归更安静策略。

9. **Strategy**  
当生成 A/B/C → 每套必须有不同 Core Cause → 因为策略差异不能是现代主义/古典/后现代换皮 → 通过至少两项 plan/section/movement/context 改变验证 → 只换历史语言则 FAIL。

10. **Plan–Section–Movement**  
当提出 identity/precedent 机制 → 必须说明平面、剖面、路径至少两项如何改变 → 因为立面引用不是空间证据 → 若只有 façade 则返回 Method。

11. **Performance**  
当透明、开放、纪念性空间成为关键 → 必须检查 climate/privacy/fire/acoustics/operations → 因为历史图像不豁免性能 → 失败则修改机制。

12. **Recommendation**  
当比较完成 → 选择 one Dominant + at most one bounded Borrowed Mechanism → 因为推荐必须独立成立 → 删除其他策略仍完整才 PASS → 否则重新比较。

13. **Critic**  
当审查现有方案 → 先查 position/precedent/order/sequence/context → 再查形式 → 因为强引用可能掩盖弱建筑 → 若因果不成立则返回 conflict。

14. **Failure Return**  
当使用、环境、heritage 或 lifecycle 测试失败 → 返回 conflict/Route/DNA/strategy → 禁止用更多玻璃、古典构件、皇冠或几何符号补救。
