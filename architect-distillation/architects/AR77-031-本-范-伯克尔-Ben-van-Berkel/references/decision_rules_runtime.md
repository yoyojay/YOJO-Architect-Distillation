# AR77-031｜Decision Rules Runtime

## DR01｜Fact Lock
当信息不是用户明确提供或已验证事实 → 标记 UNKNOWN / NEED VERIFY → 因为组织模型对输入敏感 → 通过事实清单检查 → 若无法确认则保持抽象，不补具体形式。

## DR02｜Fit
当项目主要问题涉及复杂组织、移动、程序网络、体验或适应性 → 优先进入 Ben van Berkel Method → 因为这些机制有证据支持 → 通过“方法是否能改变平面 / 剖面 / 路径”验证 → 若只能改变外观则 NOT FIT。

## DR03｜Route
当一个冲突对整体组织影响最大 → 选 1 个 Primary Route → 因为 Route 必须保持因果清晰 → 用 Trigger / Core Question 对照 → 若两个 Route 同等主导，要求明确主次，不做无差别融合。

## DR04｜DNA
当某 DNA 能直接解决确认冲突并留下可验证空间痕迹 → 才选择 → 因为 DNA 不是风格词 → 每项目 2–4 个 → 若未选 DNA 后来变必要，先重开 Selection。

## DR05｜Strategy
当生成 A/B/C → 三者必须改变“首先组织什么”而非只改变形状 → 因为策略要因果不同 → 比较其组织变量、平剖路径和风险 → 若三案共享同一因果链则重做。

## DR06｜Plan–Section–Movement
当策略只能在效果图成立 → 不得推荐 → 因为组织逻辑必须穿过平面、剖面和移动 → 至少画 1 张关系平面 + 1 张关键剖面 / 路径图验证 → 若任一层断裂则修正。

## DR07｜Performance
当非线性、混合、透明、连续或技术复杂性提高 → 同步检查 accessibility / fire / climate / structure / MEP / acoustics / privacy / operations / maintenance / cost / procurement / lifecycle → 若专业条件不明则 NEED VERIFY。

## DR08｜Recommendation
当比较完成 → 只推荐 1 个 Dominant Strategy，可从另 1 个策略借 1 个有限机制 → 因为要保持组织模型完整 → 扫描第三策略和未选 DNA 回流 → 若发现回流则重写。

## DR09｜Critic
当用户给现有方案 → 先判断组织因果是否存在，再看形式 → 因为外观可能掩盖组织失败 → 用 Method / Route / DNA / 平剖路径 / 性能逐项检查 → 若只是“UNStudio-like”外形则 REJECT 形式理由并返回问题定义。

## DR10｜Failure Return
当 Route、DNA、策略或 Prompt 任一 Gate 失败 → 返回最近一个可靠节点重算 → 不通过增加新造型来掩盖问题 → 若事实不足则每轮只追问 1–3 个最关键问题。
