# AR77-031｜Problem Routes Runtime

## Route Rule
- 每轮完整分析选择 **1 个 Primary Route**。
- 只有当第二类冲突会实质改变平面 / 剖面 / 路径时，才允许加 **1 个 Secondary Route**。
- Secondary Route 只提供一个明确补充机制，不能夺取主导。
- Route 必须由项目冲突触发，不按作品年代、建筑类型或视觉相似度选择。

---

## R1｜MOBILITY_CONFLUENCE｜多流线汇合

**Trigger**  
多交通方式、多入口、多用户速度、多层换乘或高峰 / 非高峰时段同时存在。

**核心问题**  
如何让移动成为组织程序和公共性的主骨架，而不是把交通流线塞进既定形体。

**Method**  
以 Deep Planning 读取时间、轨迹、程序和层级；把 infrastructure 当作连接空间与程序的动态原则；通过汇合、分流、可见性与捷径建立清晰系统。

**主要 DNA**  
D1 Deep Planning Matrix；D2 Infrastructure Connector；D4 Nonlinear Orientation。

**适用边界**  
车站、交通枢纽、大型公共建筑、校园或复杂多入口项目。

**风险**  
连续性过强导致步行距离、疏散、无障碍、运营分区和寻路负担上升。

**与其他 Route 的差异**  
R1 的主因是“移动系统如何组织整体”，不是展览叙事或混合程序本身。

---

## R2｜EXPERIENCE_NETWORK｜体验网络

**Trigger**  
项目需要多条叙事、参观、学习、零售或家庭生活路径，并希望人在移动中获得不同关系而非单一线性序列。

**核心问题**  
如何让路径、交叉、回看与选择产生体验，同时保持定位和程序清晰。

**Method**  
先定义体验节点与可选择关系，再选择可变 Design Model；让路径在平剖面中形成连续 / 分叉 / 交叉关系，并设置可验证的方向感与回看。

**主要 DNA**  
D3 Design-Model Translation；D4 Nonlinear Orientation；D5 Program Crossing。

**适用边界**  
博物馆、文化、教育、体验型商业、住宅等以“经历空间”为核心的项目。

**风险**  
把 loop、螺旋或双路径当作标志造型；体验复杂度超过使用需求。

**与其他 Route 的差异**  
R2 的主因是“人的体验如何展开”，而不是换乘效率或高密度混合程序。

---

## R3｜HYBRID_PROGRAM_NETWORK｜混合程序网络

**Trigger**  
多个用户群、功能、开放时段与公共 / 半公共 / 专属区域需要共存，且简单分层或分区会损失协同。

**核心问题**  
哪些程序应相遇、何时相遇、通过什么共享节点相遇，哪些必须保持独立。

**Method**  
建立 program × time × user 邻接矩阵；找到可共享节点和必须隔离的后台；用移动与空间基础设施连接不同程序，同时测试结构、服务和运营的耦合。

**主要 DNA**  
D1 Deep Planning Matrix；D2 Infrastructure Connector；D5 Program Crossing；D6 Integrated Systems Coupling。

**适用边界**  
混合用途、总部 / 校园、大型公共复合体、紧凑高密度项目。

**风险**  
“混合”变成所有功能都互相暴露；后台、安防、声学、夜间运营失控。

**与其他 Route 的差异**  
R3 的主因是“程序关系与时间共享”，移动是组织工具而不是唯一目标。

---

## R4｜ADAPTIVE_PERFORMANCE｜适应与性能

**Trigger**  
项目寿命长、使用变化快，或健康、可持续、循环性、技术协同和可重构性是核心约束。

**核心问题**  
如何让组织模型在未来变化中继续工作，而非只满足当前 brief。

**Method**  
把用户旅程、健康 / 环境目标、技术系统与变化场景纳入知识网络；用可测试指标和重组情景反向修正空间与服务组织。

**主要 DNA**  
D6 Integrated Systems Coupling；D7 Knowledge Network；D8 Future-Proof Performance。

**适用边界**  
教育、办公、健康、科研、更新改造及需要长期适应性的项目。

**风险**  
把“灵活”写成空泛口号；技术系统过度复杂；性能指标与建筑体验脱节。

**与其他 Route 的差异**  
R4 的主因是“长期变化与可验证性能”，不是视觉连续性或路径戏剧性。
