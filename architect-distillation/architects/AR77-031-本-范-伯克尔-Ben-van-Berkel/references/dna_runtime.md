# AR77-031｜Design DNA Runtime

## Selection Logic
- 每个项目只选 **2–4 个 DNA**。
- 选择标准：DNA 必须直接回答已确认的核心冲突，并在平面 / 剖面 / 路径 / 性能中至少留下两类可验证痕迹。
- Primary Route 决定首选 DNA 范围，但不要求把该 Route 的所有 DNA 全选。
- 未选 DNA 不得在 Strategy、Recommendation、Prompt、Keep 或 Next 中回流。
- 如果后来发现必须增加 DNA，先重开 Selection，再重生成受影响策略。

---

## D1｜Deep Planning Matrix｜深度规划矩阵
**判断含义**：复杂项目不能只按静态功能表组织，要同时读取时间、用户轨迹与程序关系。  
**Trigger**：多用户、多时段、多流线或程序关系在不同时间变化。  
**Spatial Operation**：建立 time × user × movement × program 矩阵，标出冲突、共享和分离，再转译为邻接与层级。  
**适用边界**：真实数据或可靠使用情景至少有一部分可获得。  
**Failure Mode**：矩阵变成图表展示，却没有改变空间决策。  
**可验证空间痕迹**：高峰 / 低峰路径不同仍可运行；共享节点与独立区域在平面上可追踪。

## D2｜Infrastructure Connector｜基础设施连接器
**判断含义**：把 circulation / access / service spine 看成连接程序与空间的主动组织原则。  
**Trigger**：项目因多个入口、交通模式、层级或服务系统而碎裂。  
**Spatial Operation**：先定义主要连接骨架，再让程序、公共节点与垂直交通依附 / 交叉，而非后补走廊。  
**适用边界**：连接确实能改善整体组织。  
**Failure Mode**：为了“流动感”制造过长路径。  
**可验证空间痕迹**：关键程序可由明确连接骨架到达；入口—节点—目的地关系可画成无断裂路径。

## D3｜Design-Model Translation｜设计模型转译
**判断含义**：使用一个抽象组织模型压缩复杂关系，但允许它被场地、程序、结构与性能持续变形。  
**Trigger**：项目关系复杂，单纯房间堆叠无法保持核心逻辑。  
**Spatial Operation**：先写出模型规则，再用至少两轮平面 / 剖面测试证明模型发生必要变形。  
**适用边界**：模型必须解释项目关系，不是借来的图标。  
**Failure Mode**：把 Möbius、螺旋、扭转等几何直接当建筑答案。  
**可验证空间痕迹**：同一组织规则能在不同层级 / 尺度中被识别，但没有机械复制同一几何。

## D4｜Nonlinear Orientation｜非线性路径与定位
**判断含义**：非线性不等于迷宫；选择、交叉、回看和捷径应提高体验，同时保留方向感。  
**Trigger**：单一路径过于僵硬，或项目需要多个叙事 / 使用选择。  
**Spatial Operation**：设置可选择分支、交叉点、回看参照与必要捷径，并在剖面中检查垂直路径。  
**适用边界**：消防、无障碍、运营与寻路允许。  
**Failure Mode**：路径戏剧性压倒效率与可读性。  
**可验证空间痕迹**：使用者能从关键节点判断来源与去向；至少存在一条清晰等效无障碍路径。

## D5｜Program Crossing｜程序交叉
**判断含义**：有价值的混合发生在被选择的交叉节点，而不是所有功能无差别开放。  
**Trigger**：不同用户 / 程序需要偶遇、协作或共享资源。  
**Spatial Operation**：识别可以共享的节点、可视关系与时间重叠；同时锁定声学、隐私、安防或后台边界。  
**适用边界**：共享产生真实使用价值。  
**Failure Mode**：公共性与透明性侵蚀专属功能。  
**可验证空间痕迹**：共享节点有明确服务对象与时间；独立运行路径仍成立。

## D6｜Integrated Systems Coupling｜系统耦合
**判断含义**：平面、剖面、移动、结构与技术系统应尽早相互校验，而非形体完成后再塞工程。  
**Trigger**：复杂跨度、连续路径、混合层级或高技术要求会改变空间组织。  
**Spatial Operation**：为每个策略建立 plan–section–movement–structure / service 联动检查，不预设结构形式。  
**适用边界**：只做建筑层级的协调判断，工程结论由专业顾问确认。  
**Failure Mode**：形式几何迫使结构 / MEP 付出不必要复杂度。  
**可验证空间痕迹**：主要路径、净高、结构深度和服务区不互相矛盾；关键剖面可解释。

## D7｜Knowledge Network｜知识网络
**判断含义**：设计把多专业知识与用户反馈转化为决策，而不是由单一作者直觉封闭完成。  
**Trigger**：健康、技术、运营、经济或使用经验对设计结果影响显著。  
**Spatial Operation**：列出关键专业 / 用户输入及其可改变的设计变量，为每轮决策保留反馈接口。  
**适用边界**：输入必须可验证，不把咨询意见自动当建筑真理。  
**Failure Mode**：信息越来越多但没有明确决策责任。  
**可验证空间痕迹**：至少能指出哪些空间关系因专业 / 用户证据而改变。

## D8｜Future-Proof Performance｜未来适应性能
**判断含义**：未来适应性要通过具体变化情景和性能指标验证。  
**Trigger**：功能更新、教学 / 工作模式变化、循环利用、健康或能源目标是长期核心。  
**Spatial Operation**：设定 2–3 个未来情景，测试分隔、服务、家具 / 设备、容量或拆装变化对组织的影响。  
**适用边界**：不能牺牲当前基本使用质量换取抽象“灵活”。  
**Failure Mode**：只写 open plan / flexible，不说明怎样变化。  
**可验证空间痕迹**：变化情景有明确调整路径；关键性能可被后续数据或专业测试验证。
