# AR77-038｜DECISION RULES
## Minoru Yamasaki

1. **当**方案先出现尖拱 / 窄窗 / 细柱 / 白色表皮  
   **→ 优先**回到 D01  
   **→ 因为**Yamasaki 的核心是 human experience，不是形式词汇  
   **→ 通过**真实使用场景 / 路径 / 停留验证  
   **→ 若失败则**删除该形式。

2. **当**环境压力 / 噪声 / 速度过高  
   **→ 优先**D02  
   **→ 因为**serenity 是对机器时代混乱的调停  
   **→ 通过**sound / pause / light / boundary / use test  
   **→ 若失败则**不要把“安静外观”当宁静。

3. **当**长路径 / 重复空间显得单调  
   **→ 优先**D03  
   **→ 因为**surprise / delight 应来自空间变化  
   **→ 通过**plan-section sequence + user event 验证  
   **→ 若失败则**删除戏剧化转折。

4. **当**大型 / 高层建筑产生压迫或恐高风险  
   **→ 优先**R3 + D04 / D08  
   **→ 因为**巨大尺度必须重新接回人体尺度  
   **→ 通过**eye-level / entry / window / ground interface / wind test  
   **→ 若失败则**不得用窄窗或 plaza 作为历史复制答案。

5. **当**预制 / 重复构件是项目条件  
   **→ 优先**R4 + D07  
   **→ 因为**工业效率不能变成无差别环境  
   **→ 通过**component / manufacturing / light-shadow / cost test  
   **→ 若失败则**取消装饰性复杂化。

6. **当**庭院 / 水 / 景观被提出  
   **→ 优先**R2 + D06  
   **→ 因为**它们必须解决停留 / 微气候 / 社交 / 声环境  
   **→ 通过**climate / water budget / accessibility / maintenance / use test  
   **→ 若失败则**删除水景或形式化庭院。

7. **当**立面构件强调阴影 / 节奏  
   **→ 优先**D05  
   **→ 因为**光影必须与结构 / 围护 / 气候职责一致  
   **→ 通过**section / solar / envelope / structure validation  
   **→ 若失败则**不能保留纯装饰 screen。

8. **当**公共展示希望“更有惊喜”  
   **→ 优先**R5  
   **→ 因为**delight 应服务发现 / 学习 / orientation  
   **→ 通过**visitor journey / accessibility / crowd flow  
   **→ 若失败则**移除 spectacle。

9. **当**A/B/C 只是拱形 / 柱列 / 水景 / 材料变化  
   **→ 优先**重做  
   **→ 因为**策略必须因果不同  
   **→ 通过**不同 Primary causal mechanism 验证  
   **→ 若失败则**Strategy Gate FAIL。

10. **当**Recommendation 想吸收 A+B+C  
    **→ 优先**只保留一个 Dominant  
    **→ 因为**Dominant 必须可独立成立  
    **→ 通过**最多一个 Borrowed Mechanism  
    **→ 若失败则**Recommendation Gate FAIL。

11. **当**Prompt 自动补 travertine / marble / aluminum / concrete / narrow window / pointed arch / fountain  
    **→ 优先**Prompt Fact Lock  
    **→ 因为**历史材料 / 构件不是当前项目事实  
    **→ 通过**KNOWN / selected Route / Dominant / Borrowed / Selected DNA / verified site-climate-light 追溯  
    **→ 若失败则**删除或泛化。

12. **当**方案只宣称“人本”却忽略治理 / 维护 / 社会使用  
    **→ 优先**Contemporary Correction  
    **→ 因为**体验目标不能替代真实社会结果  
    **→ 通过**operations / maintenance / accessibility / safety / stakeholder use 验证  
    **→ 若失败则**返回 Project Conflicts。
