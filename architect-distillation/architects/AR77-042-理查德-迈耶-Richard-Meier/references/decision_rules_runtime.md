# AR77-042｜Architect-Specific Decision Rules

> 条件 → 优先 → 因为 → 验证 → 失败后回退；这些为 AR77 为真实项目编制的 **可审查决策规则**，不冒充 Richard Meier 本人逐条提出。

## Hard Rule Catalogue

**RULE F｜FACT**
- 当重要场地/功能/光照信息是 UNKNOWN → 优先保持关系性假设 → 因为具体化等于编造 → 通过资料出处列表和图纸复核验证 → 若失败则撤回具体断言，问至多3个问题。

**RULE FIT｜适配**
- 当项目的唯一目标是「迈耶白色风格」 → 优先解释方法及可用条件，给 NOT FIT（作为风格复制需求） → 因为方法是空间秩序和体验 → 通过用户是否允许解决可测试建筑问题验证 → 若失败则不制作外观化方案。

**RULE P｜功能秩序**
- 当公私/观众与后勤冲突 → 优先在平面和剖面上固定用户边界 → 因为 Smith House 与 MACBA 均从可用的使用组织形成空间秩序 → 通过邻接与访问权限矩阵验证 → 若失败则重分配功能边界。

**RULE S｜场地坐标**
- 当地形/城市秩序与组团到达发生冲突 → 优先选择符合实际地形与功能的主轴 → 因为 Getty 案例由地形和城市格局参与生成秩序 → 通过总平、剖面与步行/物流路径验证 → 若失败则先调整轴线而非建筑表皮。

**RULE G｜有效几何**
- 当第二网格或偏移只是图形趣味 → 优先取消 → 因为缺少问题上的因果贡献 → 通过使用面积、路径与结构造价对照验证 → 若失败则退回单一可读秩序；D3 不选入。

**RULE ROUTE｜主路线**
- 当多个 Route 似乎均能解释项目 → 优先最能决定平面拓扑和项目红线的主冲突 → 因为 Route 是问题分流不是设计形象 → 通过该 Route 解决失败是否导致项目失败验证 → 若证据不足则标 ROUTE_UNRESOLVED 并问问题。

**RULE DNA｜必要 DNA**
- 当某 DNA 不能产生可画/可测试的空间痕迹 → 优先排除 → 因为术语堆叠不会产生可调用判断 → 通过一页验证图纸/测试任务审查 → 若失败删掉 DNA 并阻止回流。

**RULE MOVEMENT｜路径**
- 当连续坡道/观景路径增加旅程但无活动价值 → 优先高效且可选择的路线 → 因为 Atheneum 坡道来自历史场所导览目的 → 通过真实路径、可达率、疏散容量、无障碍等效测试 → 若失败撤除形式化坡道。

**RULE DAYLIGHT｜环境**
- 当自然光与展示/隐私/能源目标冲突 → 优先功能适宜且可控的光环境 → 因为 Getty 官方记录采用遮阳与过滤配合自然光 → 通过眩光/日光/热负荷/收藏保护验证 → 失败则调整开口关系或分区，不默认白玻璃。

**RULE STRATEGY｜因果差异**
- 当 A/B/C 只是颜色、造型、几何强弱不同 → 优先重做导致功能和路径差异的三个机制 → 因为三案必须产生不同计划/剖面/运营结果 → 通过主冲突、动线、验证目标三列不相同检查 → 失败则不能进行推荐。

**RULE RECOMMEND｜主方案**
- 当推荐混入三案、未经选择的 DNA 或 Rejected Strategy → 优先只保留可独立成立的单一 Dominant 和最多另一个方案的一个有限机制 → 因为混合会失去可追责因果链 → 通过字段审计 `Dominant/Borrowed/Rejected/Why/Unresolved/Need Verify` 验证 → 若失败则重做推荐。

**RULE CRITIC｜审查**
- 当现有视觉表现与平剖空间因果相矛盾 → 优先审图/功能测试而非接受效果图 → 因为光影美感不能证明能用 → 通过原始总平、平面、剖面、门禁/路径/性能验证 → 失败返回 Method/Route/DNA。

**RULE VISUAL｜事实锁**
- 当 Prompt 生成无可追溯的材质/屋面/幕墙/轴线角度 → 优先删改为关系或性能语言 → 因为典型作品细节不能替用户代设计 → 逐项 Prompt Fact Lock 扫描 → 不合规则禁止输出。

**RULE FAIL｜失败返回**
- 当当地消防/无障碍/气候/预算/运维否决主策略 → 优先记下冲突并回到项目事实和主 Route → 因为美观不能越过专业边界 → 由相关专业完成校核 → 未通过不进入确认或 Handoff。
