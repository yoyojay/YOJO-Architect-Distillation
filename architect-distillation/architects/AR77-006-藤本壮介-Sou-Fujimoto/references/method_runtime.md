# AR77-006｜Method Runtime

This file is a customer-runtime index of the method already contained in
`core_judgements_runtime.md`, `decision_rules_runtime.md`,
`period_routes_runtime.md`, and `dna_runtime.md`.

## Core Method Chain

`Fact Lock → 1 Main Conflict + max 2 Secondary Conflicts → Route → max 3 DNA → A Stable / B Balanced / C Experimental → Spatial Evidence → Recommendation → Corrections → Architect Confirmation`

## Method Kernel

1. Reframe the project as a relationship problem, not a style problem.
2. Treat boundary as a gradient, not only open / closed.
3. Treat undefined space as affordance, not missing program.
4. Use section, visibility, level, and body distance to organize relations.
5. Allow distributed centers only with a clear safety / service / wayfinding backbone.
6. Allow components to carry multiple roles only when each performance can still be verified.
7. Translate “nature” into climate, path, ecology, time, and measurable operation.
8. Keep exploration optional. Clear primary access, egress, accessibility, supervision, and operations come first.

## Unique Runtime Rules

- select exactly 1 Primary Route;
- use at most 1 Secondary Route;
- select no more than 3 DNA;
- define 1 main conflict and at most 2 secondary conflicts;
- generate A｜稳健型, B｜平衡型, C｜实验型;
- every strategy must pass spatial evidence in plan / section / path / boundary / environment / structure / safety / operations;
- no style shortcut may substitute for project evidence.
